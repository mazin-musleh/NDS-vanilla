# NDS JS Audit — DRY/KISS + consistency rules (JSD)

DRY/KISS and cross-file-consistency detection catalog for `nds-js-audit`. Read during Phase 2/3 of a `dry` run (or any run with no rule-group filter). **JSD-05** (cross-file body dedup) needs the full tree — single-file `dry` skips it with the Phase 4 banner. **JSD-15** applies the canonicals in `PERSONA.md` (sibling file) per-file. Severity drives Phase 5 fix order. Audit flow: `SKILL.md`.

#### JS DRY/KISS (JSD)

| ID | What to detect | Severity | Fix |
|---|---|---|---|
| JSD-01 | **Direct `data-state` access that bypasses `NDS.State`.** `node scripts/check-js-rules.mjs` finds the sites and applies the carve-outs: (a) `setAttribute` / `getAttribute` / `removeAttribute` / `hasAttribute` against `'data-state'`, or a `dataset.state` write; (b) the same on a `data-<prefix>-state` twin (`data-toast-state`), which splits one lifecycle across two attributes; (c) a selector or HTML template naming a token the file itself writes through `NDS.State`. A token outside the state vocabulary (`open` `closing` `opening` `closed` `show` `hide` `shown` `hidden` `active` `inactive` `selected` `expanded` `collapsed`) is the component's own classification and never a finding. A token the file never writes belongs to another component: a selector reads its state, a template ships its canon (Accordion's default-open `data-state="open"`). The script's `ALLOW` holds the selectors a writer list cannot decide, each with its reason. Judge only what the script prints.<br><br>**Fix routing (c).** When the component already tracks the state in a structure (`_js/nds-main-nav.js` `_openDropdowns`), read that structure instead, but only when its membership lasts exactly as long as the token the selector reads. | HIGH | (a) `NDS.State.add/remove/has/get/set/clear/apply`; any state → `NDS.State.get(el) !== ''`. (b) Move the twin onto `data-state` with component tokens (`NDS.State.add(toast, 'toast-show')`); two real axes are space-separated tokens on one `data-state`. (c) Iterate with `NDS.State.has`, or track a Set of instances; a template drops the attribute and calls `NDS.State.set` after `innerHTML`. Three files repeating (c) → a JSD-05 candidate for a core query helper. |
| JSD-02 | `check-js-rules.mjs` finds it. Direct access on `data-status` — `setAttribute`, `getAttribute`, `removeAttribute`, `hasAttribute`, or `dataset.status` read or assignment (`el.dataset.status === 'success'`). The `hasAttribute('data-status')` form bypasses `NDS.Status` just like the others. | HIGH | Use `NDS.Status.set/get/clear`. Status is a single value, not a set. For `hasAttribute('data-status')` reads, use `NDS.Status.get(el) !== ''`. |
| JSD-03 | **Hardcoded layout pixels bypassing the token layer.** A breakpoint number written into JS silently drifts from `NDS.breakpoints` on every re-audit. Off-by-one literals like `958`, `601` or `961` are the common shape, because media queries use inclusive edges while `NDS.breakpoints` picks one side as canonical; a literal fallback after a CSS-variable read also hides a missing-CSS-var bug when the fallback silently takes over. `check-js-rules.mjs` finds all three sub-shapes: **(a)** a viewport comparison (`window.innerWidth`, `document.documentElement.clientWidth`, `document.body.clientWidth`) against an integer in `[400, 2000]`; **(b)** a 768/1024/1280/1440 fallback after `getPropertyValue(...)` parses a CSS variable; **(c)** an integer in `[400, 2000]` inside a `min-width` / `max-width` / `min-height` / `max-height` media feature passed to `window.matchMedia(...)`. | MEDIUM | Viewport comparisons and `matchMedia` literals → use `window.matchMedia(NDS.breakpoints.mobile/tablet/'tablet-max'/desktop/'desktop-max'/'large-desktop').matches`. If the specific pixel threshold isn't in `NDS.breakpoints`, either add it to core or align the component to the closest existing token (e.g., `958` → `'desktop'` at 960px, `601` → `'tablet'` at 600px, `961` → `'desktop'` at 960px). Fallback literals → ensure the CSS variable is always defined in base styles so the fallback never fires, or extract the literal to a SCREAMING_SNAKE_CASE module-scope constant with a rationale comment explaining why JS needs the value. |
| JSD-04 | **Re-implemented locale/direction check that duplicates `NDS.lang` / `NDS.isRTL` / `NDS.isArabic`.** A document-level read of `dir` or `lang`, or a derivation from one (lowercase, prefix-split, compare against `'ar'`), re-derives what core already answers live, and each copy can drift from it. `check-js-rules.mjs` finds both sub-shapes: **(a)** direction reads and **(b)** language reads on `document` / `document.documentElement` / `document.body`.<br><br>**Explicitly NOT a finding** (do NOT flag):<br>- **Pre-loader standalone scripts.** A file that runs before `nds-loader.js` has no `NDS` to read — the document-level derivation IS the only option. Detection: the file's own `NDS.*` uses (if any) are existence-guarded (`window.NDS && NDS.<X>`), and it is not in the loader's `COMPONENTS` registry. Same reasoning as JSD-08's pre-loader carve-out. Motivating examples: `_js/events/nds-theme-hajj.js` and `_js/events/nds-theme-foundation-day.js` `LANG` (~L84 / ~L81) — event theme PACKs whose documented shape is a self-contained `<script src>` in `<head>`; their only `NDS` touch is a guarded `NDS.Swiper` call. Their local `esc` / `safeUrl` helpers are exempt from JSD-10 for the same reason.<br>- **Full-tag reads.** `document.documentElement.lang` passed whole to an API that needs the region or script subtag: `Intl.*` locales, `new Intl.Locale(tag).maximize()`, `SpeechRecognition.lang`. `NDS.lang` keeps only the primary subtag (`ar-SA` → `ar`), so it cannot answer. Cite: `_js/nds-voice-input.js` `getLanguage`, `_js/nds-accessibility.js` `noLetterSpacing`, `_js/nds-date.js` `format`; core's own `NDS.formatNumber` reads the same way.<br>- Per-element `direction` reads: `getComputedStyle(el).direction === 'rtl'` (or `=== 'ltr'`) where `el` is NOT `document.documentElement` / `document.body`. `NDS.isRTL` is a document-level signal and cannot answer per-instance direction questions — a component nested inside a `dir="…"` wrapper or styled via CSS `direction:` (e.g., chart canvases, embedded RTL widgets inside an LTR shell) must resolve direction at the element level. Motivating example: `_js/nds-chart.js:404` reads `getComputedStyle(this.el).direction` for per-chart RTL handling — a legitimate use case that `NDS.isRTL` cannot satisfy. | MEDIUM | Use `NDS.isRTL` (live getter) or `NDS.lang` / `NDS.isArabic`. |
| JSD-05 | **Promotion candidate.** Two sub-shapes, both requiring no equivalent in `nds-core.js`: **(a)** a helper with a near-identical signature and body in two or more component files; **(b)** a canonical idiom with a body worth sharing, written inline in **three or more** component files, whether or not any file wraps it in a named helper. The higher threshold for (b) (3 files, vs (a)'s 2) keeps a two-site coincidence from minting an API. `check-js-rules.mjs` lists the candidates for (a) when two files declare a same-named helper with ~70% the same body, and for (b) when the HTML-escape idiom is inline in three or more files; a helper copied under different names and the debounce/throttle idiom are yours. For an in-scope idiom, count DISTINCT files; a file contributes once however many sites it holds.<br><br>**Body gate — the idiom must be multi-statement or carry a branch.** A single expression with no branches cannot diverge between copies, so a shared implementation prevents no bug-fix drift; promoting one buys a project-local name for something the reader already parses fluently, and pays for it in core bytes on the reveal-gating main bundle plus a permanent published-API commitment (removal later needs a CHANGELOG Migration entry). In scope from JSD-10's idiom list: HTML escape, debounce/throttle. Out of scope: **clamp** — `Math.min(Math.max(v, lo), hi)` is one expression, and JS ships no `Math.clamp`, so the composition IS the idiom; `_js/nds-ipv.js` `clamp` (~L123) plus the inline sites in `_js/nds-filter.js` (~L1889-1890) and `_js/nds-pagination.js` (~L738, ~L1565) clear the 3-file count and still correctly produce no finding.<br><br>**Explicitly NOT a finding** (do NOT flag):<br>- Sub-shape (b) matches where the idiom's operands make the sites semantically unrelated — the shape is shared but no single signature serves every caller. Record as a Gap.<br>- Idioms the language ships natively (route to the ponytail `PONY-STD` lens instead of minting an `NDS.*` name): JS has no `Math.clamp`, so clamp stays in scope here, but a hand-rolled `Array.from` / `flat` / `structuredClone` equivalent does not. | MEDIUM | Propose an `NDS.*` API name and list every call site. Typical candidates: focus-trap, scroll-lock, `getComputedStyle` readers, `matches()` / `closest()` helpers, RAF batchers, event-delegation factories, z-index stackers, `aria-expanded` toggles. Surface the candidate in the Phase 4 report; editing `nds-core.js` to add the helper + migrating every call site is a Phase 5 action the user approves per-candidate via `promote <api-name>` (see "Applying promotion candidates" in `FIX.md`). |
| JSD-06 | DOM read after write in the same frame: a style or class write followed by a layout read (`getBoundingClientRect`, `offset*`, `client*`, `scroll*`, `getComputedStyle`) inside a loop body forces a synchronous layout on every iteration (N writes × N reads in one synchronous block). One-shot write-then-read sequences are not thrashing. `check-js-rules.mjs` finds the loop form.<br><br>**Explicitly NOT a finding** (do NOT flag):<br>- Staged-measurement patterns: a write to `style.cssText` / `style.visibility` / `style.position` that puts an element into a measurable off-screen state, followed by `offsetHeight` / `offsetWidth` / `getBoundingClientRect()` reads. The read semantically depends on the write (the element must be staged before it can be measured), so "batch reads before writes" does not apply. Require an inline comment near the write confirming the staging intent to earn this exemption — otherwise it's indistinguishable from a thrash loop. | LOW | Batch reads before writes: collect every layout read into locals first, then apply all writes. Exemplar: `_js/nds-core.js` `NDS.flipPosition` (~L1573) — collects `triggerRect` / viewport dims into locals before any positional write. |
| JSD-07 | **Component contract conformance.** A `_js/nds-{name}.js` file whose public surface does not match one of the two shapes the loader expects. Factory components must expose `NDS.{Name}.init()`, `NDS.{Name}.reinit()`, and `NDS.{Name}.create(el)`. Singletons must expose `NDS.{Name}.init()` plus their component-specific methods. The namespace `{Name}` must match the component's `_js/nds-loader.js` `COMPONENTS` registry name, and both are the file suffix in PascalCase split at its hyphens (PERSONA entry 9): `nds-custom-select.js` → `NDS.CustomSelect`, `nds-taginput.js` → `NDS.Taginput`, `nds-otp.js` → `NDS.Otp`.<br><br>`check-js-rules.mjs` finds a loader-registered component with no `init()`, and a registered factory (`create(el)`) with no `reinit()`. It skips a `create(options)` module and one whose banner declares a singleton, and it does not check the namespace spelling.<br><br>**Explicitly NOT a finding** (transient-surface exemption): a module whose `create()` takes an OPTIONS OBJECT and builds a new surface — PERSONA entry 3.3's `create({…})` + `dismiss(target)` bucket — rather than taking an element and instancing it. Its `create` is the constructor entry for a surface with a finite lifetime, not a per-element factory, so the factory triple does not apply and a missing `reinit()` is correct, not drift. Such a module may ALSO run a one-time document sweep in `init()` (wiring close buttons on server-rendered instances) without becoming a factory — the sweep builds no instance and registers no expando. Confirm via the loader entry: registered with `init` alone and no `reinit` call site anywhere. Cite: `_js/nds-alert.js` (`NDS.Alert.create(options)` + `dismiss` / `dismissAll`, `init()` sweeps `.nds-alert` for close buttons) and `_js/nds-feedback.js` (`NDS.Feedback = NDSFeedback`, not loader-registered under its own name) — neither exposes `reinit()`, and nothing calls one.<br><br>**Explicitly NOT a finding** (composable-widget exemption): a module whose constructor entry is invoked by SIBLING components rather than by the loader — absent from the loader's `COMPONENTS` registry, or registered with a `refresh` hook in place of `reinit` — JSD-11's documented composable shape, seen from the contract side. Its surface is `create(el, options)` + a lookup (`getInstance`), with no `init()`/`reinit()`, because there is no page sweep to run: the owning component decides when an instance exists. A missing factory triple is correct here, not drift. Cite: `_js/nds-sort.js` `NDS.Sort` (`create` / `getInstance`), built by `_js/nds-filter.js` and `_js/nds-table.js`. Sort is registered with a `refresh` hook, so the loader never calls a `reinit`. Verify: the `_js/nds-loader.js` entry is absent or carries `refresh`, and at least one sibling calls `NDS.<Name>.create(`. | MEDIUM | Restructure the module to match the shape of the closest peer (factory example: `_js/nds-tabs.js`; singleton example: `_js/nds-theme.js`). Inconsistent shapes force every reader to relearn the API per component and block the loader from treating components uniformly. For utility modules covered by the exemption above, no fix is required — but a one-line comment near the namespace export naming the consuming components keeps future audits from re-flagging. |
| JSD-08 | **Dead defensive guards.** `check-js-rules.mjs` finds them: inside a function, a guard (`typeof NDS`, `NDS?.`, `NDS &&`, `window.NDS &&`, `NDS.X?.`, `NDS.X &&`, `if (!NDS.X)`, `typeof NDS.X`) on what the loader guarantees before any `init()`: `NDS` itself, a core utility (the script's `CORE_UTILS`), the loader's `NDS.Init`, or the file's own namespace. The guard implies an uncertainty the loader contract denies. A value utility (`NDS.lang`, `NDS.isRTL`, `NDS.isArabic`, `NDS.focusableSel`) counts only in its `?.` form, since `NDS.isRTL && x` reads a value. Module top level runs before the loader and passes. A comment above the guard makes the line `verify`: it exempts only when it names the namespace and says why it is optional. A sibling component's guard is JSD-12's. A multi-part guard (`NDS && NDS.Form && NDS.Form.validate`) collapses to the final call when the method sits in an always-assigned object literal. `typeof window` / `typeof document` is no JSD-08 finding: when neither `_js/nds-core.js` nor `_js/nds-loader.js` guards the environment, a component's own guard is unreachable, a ponytail `PONY-DEL`. | LOW | Remove the guard. If the call site truly cannot assume the dependency (e.g., code that runs before the loader or outside the component lifecycle), route it through the loader or defer the call — do not hedge at the call site. |
| JSD-09 | **Teardown references properties never stored, or stored handles never invoked.** A teardown that dereferences something nothing stored is dead code pretending to clean up: `removeEventListener` receives `undefined` and silently does nothing, a stored `NDS.on*` unsubscribe nobody calls leaves its pooled subscriber leaking (and stacking on re-init), and a collection that is iterated but never filled releases nothing. Four sub-shapes: **(a)** a `this.handlers.{name}` key that teardown reads and nothing assigns; **(b)** `removeEventListener(..., <owner>._handlerName)` or `<owner>.<prop>.disconnect()` where the property is never assigned (e.g. `this.observer.disconnect()` with no `this.observer = …`); **(c)** a stored `<owner>._off* = NDS.on*(...)` handle that no teardown or re-init path calls; **(d)** an instance field assigned an empty collection (`[]`, `new Set()`, `new Map()`) and iterated in a teardown path (`this.observers.forEach(o => o.disconnect())`) with no `.push` / `.add` / `.set` writing it anywhere in the file. `check-js-rules.mjs` finds the dotted forms of all four. Not covered: the loop-over-keys form `this.handlers[name]` and a zero-arg `<owner>.<prop>()` teardown call. For (c) on a closure variable it hands you one judgement: a page-lifetime subscription behind an init latch leaks nothing on re-init.<br><br>**Explicitly NOT a finding**: teardown keys assigned via destructuring (`const { foo } = this.handlers`) or assigned in a branch the detector can't statically see (e.g., conditionally stored inside a framework callback). When in doubt, confirm the binder's shape first — don't emit a false positive on dynamic code. | LOW | Sub-shape (a): store the handler under the exact key teardown reads, or better, drop the map and attach with `{ signal }` (PERSONA entry 6). Sub-shape (b): either assign `<owner>._handlerName = function...;` before the matching `addEventListener`, or replace with an `AbortController` + `{ signal }` pattern. Sub-shape (c): invoke the stored handle in the teardown path — e.g., `if (drawer._offResize) drawer._offResize();` then `delete drawer._offResize;`. Alternatively, delete the teardown entry if the listener's lifetime is managed differently (AbortController, innerHTML reset, component destruction). Sub-shape (d): delete the empty-collection field and its teardown forEach block — the resources the field pretends to track are managed elsewhere (or were never tracked at all). If the field is supposed to track something currently un-stored, fix the storage shape instead by adding the `.push` / `.add` writes at the call sites that create those resources. |
| JSD-10 | **File-local helper shadows an existing `NDS.*` utility.** The natural counterpart to JSD-05: JSD-05 watches for *promotion* candidates (duplicates across ≥2 component files with no equivalent in core); JSD-10 watches for *demotion* candidates (a single component file defines a helper that core already exposes). Once a helper is promoted to core, every file-local copy becomes dead duplication — each one is a correctness hazard because future bug fixes to the core implementation won't propagate to the shadowed version.<br><br>`check-js-rules.mjs` lists a local function that carries the name of a core function, and a local HTML-escape re-implementation (exempt only when the file runs before the loader). Everything below the name match is yours.<br><br>Detection: for any `function name(...)` or class-method `name(...)` declared inside a component file, whitespace-normalize its body and compare it against `NDS.<name>` in `_js/nds-core.js`. Fire the finding when EITHER (1) OR (2) holds:<br><br>**(1) Overlap path** — ≥65% token overlap AND comparable argument shapes. The 65% threshold catches unhardened variants of a core helper: a local copy that lacks the null guard, the `String(...)` coerce, or other hardening lines core adds. Those hardening lines are typically the first 25–35% of core's body, so a stricter gate (e.g. 90%) rejects exactly the cleanup targets the rule exists for — don't re-tighten it.<br><br>**(2) Canonical-idiom path** — both bodies match the same canonical DOM idiom AND the signatures are comparable (same argument count, same return type). This path catches divergent implementations of the same pattern. Canonical idioms currently recognized:<br>- **HTML escape**, either form (the script finds both): the `createElement(tag)` → text-safe assign → read `.innerHTML` round-trip, or a chained `String.replace` mapping `&` `<` `>` `"` `'` to entity references. Core's `NDS.escapeHtml` covers all five characters, so any local copy, either form, is a deletion target routed to core.<br>- **Clamp**: `Math.min(Math.max(v, lo), hi)` (any argument order)<br>- **Debounce/throttle**: a stored timer/flag + `setTimeout`/`requestAnimationFrame` + inner function call<br><br>Canonical-idiom recognition can be extended as audit runs reveal new duplicate-with-divergent-syntax patterns (record as a gap observation when a pattern recurs in 3+ files).<br><br>**(2b) Divergent-partial path** — an inline expression that recomputes a core helper's job while covering only SOME of its inputs or guards. Token overlap is low by construction (core's body is the superset), so paths (1) and (2) both miss it, yet it is the more dangerous shape: the local copy is not merely duplicated, it is WRONG on the cases core handles. Detection: for a call site reading ambient page geometry, page facts, or a shared convention, check whether a core helper answers the same question; if so, enumerate the branches core covers and the site does not. Fire the finding when the site drops a source core reads, a clamp core applies, or a null-guard core carries. Severity for this path is the correctness cost, not LOW: rate it MEDIUM when a dropped branch produces wrong output on a reachable page shape.<br><br>**(3) Getter-shadow path** — a `const`/`let` initializer expression that re-derives a core **live getter's** exact read (e.g. `window.matchMedia('(prefers-reduced-motion: reduce)').matches` where core exposes `NDS.prefersReducedMotion`). The function-shaped detection above misses these because there is no local helper — the duplication lives in a single expression.<br><br>Record both locations (component helper + core helper) in the finding so the user can verify the overlap visually before deleting.<br><br>**Explicitly NOT a finding** (do NOT flag):<br>- Helpers with the same name as a core utility but meaningfully different behavior — e.g., a component `escapeHtml` that strips tags rather than encoding them, or one that additionally trims whitespace. Name collision alone is not grounds for a finding; body equivalence is the gate.<br>- Helpers where core's version has a different arity or return type (e.g., core returns a Promise, component version is synchronous). Swapping would break callers — surface it as a gap, not a finding.<br>- Intentional forks of a core helper that a comment within 3 lines above explicitly justifies (e.g., `// Local copy with IE11 workaround; core version assumes modern API`). The annotation-exemption pattern mirrors JSS-01 / JSP-05.<br><br>JSD-10 fires at LOW severity because file-local duplicates are not dangerous on their own — they're cruft that grows confusing over time as core evolves and the forks diverge silently. | LOW | Delete the file-local helper definition. Rewrite every call site in the same file from `helperName(...)` / `this.helperName(...)` to `NDS.<helperName>(...)`. See `_js/nds-core.js` for the authoritative definition. If callers relied on a different method shape (e.g., instance-bound `this.helperName`), replace with the core call at the site and let the instance reference fall out of scope. **Deliberate-fork branch:** when the local helper is a behavior-different or hardened fork the swap would regress — a preserve-as-authored URL allowlist where `NDS.safeUrl` would normalize relative/`#` hrefs to absolute — do NOT delete it; add the fork-rationale annotation comment instead (satisfies the intentional-fork carve-out; mirrors JSD-12's annotation fix). Motivating skip: `_js/nds-editor.js` `safeUrl` (~L120, a non-normalizing scheme allowlist returning a boolean, not core's normalized href-or-null). |
| JSD-11 | **Loader-contract pretender — `init()` exposed but never invoked.** A module whose namespace `NDS.<Name>` is absent from the `COMPONENTS` array of `_js/nds-loader.js` but exports `NDS.<Name>.init`, where EITHER **(a)** the `init` body does meaningful DOM work (a `document.querySelectorAll` plus per-element setup, listener attachment, attribute writes other than a sentinel marker) that nothing ever fires, OR **(b)** an API-adjacent comment or trailing usage block claims surface or behavior the module doesn't have — a loader-contract claim on an unregistered namespace, documented parameters an argless body ignores, or usage examples invoking statics/methods that don't exist. Both shapes are dead-code-pretending-to-conform: (a) leaves a `querySelectorAll` walking the DOM and silently doing nothing because no caller fires it; (b) misleads the reader about why the method exists. `check-js-rules.mjs` finds sub-shape (a): an unregistered namespace whose `init()` does DOM work and that no `_js/` file, no loader entry and no doc or example page calls. Sub-shape (b) is yours.<br><br>**Explicitly NOT a finding** (sub-shape (b)):<br>- Modules where `init` is genuinely a no-op AND the comment honestly describes lazy initialization (e.g., "Lazily initialized on first `show()` call; nothing to do at page load"). Complements JSD-07 (contract conformance for loader-registered modules) by covering the inverse. | LOW | Three options by the module's actual purpose: (1) **Register** in `_js/nds-loader.js` if `init` should actually run on every page (add `COMPONENTS` entry with selector or `universal: true`). | JSD-12 | **Unannotated sibling-component soft-dependency guard.** Sibling existence depends on bundling and load order, so a guard on one may be load-bearing; the finding is silence about whether it is. `check-js-rules.mjs` lists every guard on a sibling namespace (any `NDS.X` outside `State`, `Status`, `Init` and the file's own: `NDS.X?.`, `if (!NDS.X)`, `NDS.X &&`, `|| !NDS.X`) that no comment in its scope names, where the scope is the outermost function or method with its leading comment, or the `// ----` section header above it. It also lists a raw `NDS.X.method()` in a file that guards X elsewhere, unless the same statement, an early return in the same method, or an enclosing `if (NDS.X)` guards it. Every line it prints is `verify`. Judge: a named cross-reference covers a guard when its comment names the sibling, or names an in-file scope that carries the rationale (`_js/nds-taginput.js` `_strictReject` points to `addTag`); a raw call is a latent TypeError unless that path cannot run without the sibling. Code that runs before the loader is out of scope. | MEDIUM | Add an annotation comment within 3 lines above the guard that names the sibling AND states why it's optional. Template: `// Soft dependency — <component> no-ops <feature> if <NDS.Sibling> isn't bundled.` If the dependency is actually hard (the sibling is always shipped with this component in every bundle), delete the guard outright — let the call throw if the contract is violated, so future drift is loud. If three or more components carry the same guard against the same sibling, surface as a JSD-05 promotion candidate (the cluster suggests the dependency should be lifted to a shared abstraction). |
| JSD-13 | **Hardcoded transition timing instead of `NDS.transitionSpeed()`.** `check-js-rules.mjs` finds it: a `setTimeout` whose delay is 150, 200, 250, 300 or 400 (a literal, a same-file `const` or `const` object property, or either plus at most 100), in the same function as an `NDS.State` add / set / remove of a transition token (`closing` `opening` `show` `hide` `shown` `hidden` `entering` `exiting` `collapsing` `expanding`, also as `<prefix>-<token>`), whose callback clears that same element: `NDS.State.clear` / `remove` / `set` on it, `hidden` set or removed, or `.remove()`. That is "set token, wait for the CSS transition, clear token", and the literal drifts from `--nds-transition-speed`. A comment above it makes the line `verify`: a stated reason the duration is fixed exempts it. A timer inside an `NDS.debounce`-wrapped handler is JSP-07's. | LOW | Replace the literal with `setTimeout(fn, NDS.transitionSpeed())` — or, when the timer's job is "wait for this element's transition to finish", with `NDS.onTransitionEnd(el, fn)`. The helper at `_js/nds-core.js` `NDS.transitionSpeed` (~L1115) reads `--nds-transition-speed` from `:root` once and memoizes the result, so per-call cost is a single property read. JSD-14 has the highest false-positive risk in JSD.
