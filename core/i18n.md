<section id="i18n-overview" class="nds-content-section nds-doc-overview">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Overview</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

NDS writes its own words in the page's language: button labels, screen reader labels, error messages, month names. Each NDS word in a canon carries a `data-i18n` marker, and NDS writes it from the pack of the page's language. The words a script writes come from the same pack.

A pack is one JSON file per language, such as `assets/i18n/ar.json`. English needs none: it is in the markup and the scripts, so an English page loads no pack. The page picks the language with `lang` on `<html>`, and NDS loads the pack when its scripts start. Your own words carry no marker and are never translated: write them in the page's language.

Pick another component when:

- you need to show a date in the page's language: [Date](../core/date)

</div>
  </div>
</section>

      <h2 class="nds-section-title">Usage</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

Set the language on `<html>`. The base language names the file: `ar-SA` loads `ar.json`.

<script type="text/html" id="i18n-lang" data-canon data-preview="none">
<html lang="ar" dir="rtl">
</script>

Each NDS word in a canon names its section and key in a marker. Keep the markers when you copy a canon: NDS writes those words in the page's language. `data-i18n` marks an element's text, and `data-i18n-aria-label` and its siblings mark an attribute.

<script type="text/html" id="i18n-marker" data-canon data-preview="none">
<button type="button" class="nds-close nds-modal-close nds-btn nds-subtle nds-icon-only" aria-label="Close" data-i18n-aria-label="modal.close">
  <i class="nds-icon nds-hgi-cancel-01" aria-hidden="true"></i>
</button>
</script>

Change a few texts with `window.NDS_I18N`, in `<head>` before the NDS scripts. Name each text by its section and key from the [Word List](#i18n-words). The keys you leave out keep the pack's text.

{%- comment %} The <script> below would end a canon, so the code sits in a capture. {% endcomment %}
{%- capture i18n_override %}
<head>
  <script>
    window.NDS_I18N = Object.assign(window.NDS_I18N || {}, {
      forms: { required: 'يرجى تعبئة هذا الحقل' },
      pagination: { prev: 'السابق', next: 'التالي' }
    });
  </script>
</head>
{% endcapture %}

<script type="text/html" id="i18n-override" data-canon data-preview="none" data-escaped>
{{ i18n_override | strip | escape }}
</script>

Add a language NDS does not ship, such as French: put its words in `window.NDS_I18N`, in a script file of your own that every page loads before the NDS scripts. The words you leave out show in English. Never add a file to `assets/i18n/`: an NDS update replaces that folder.

<script type="text/html" id="i18n-language" data-canon data-lang="js" data-preview="none">
// site-i18n.js, on the French pages
window.NDS_I18N = Object.assign(window.NDS_I18N || {}, {
  forms: {
    required: 'Ce champ est obligatoire',
    select_at_least: { one: 'Choisissez au moins 1 option', other: 'Choisissez au moins {n} options' }
  },
  pagination: { prev: 'Page précédente', next: 'Page suivante', page: 'Page {n}' }
});
</script>

Give your own component its text with `NDS.i18n.getStrings()`. Its English goes in the call. Each other language goes in `window.NDS_I18N`, under your component's name.

<script type="text/html" id="i18n-strings" data-canon data-lang="js" data-preview="none">
const strings = NDS.i18n.getStrings('booking', {
  title: 'Book a visit',
  seats: { one: '{n} seat left', other: '{n} seats left' }
});

heading.textContent = strings.text('title');
// set() writes the text again once the language file is in
strings.set(counter, 'text', 'seats', { n: 3 });
</script>

<section id="i18n-behavior" class="nds-content-section nds-doc-behavior">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Behavior</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

### Lookup Order
{: .nds-block-title}

NDS looks for each word in this order: your `window.NDS_I18N` override, the pack, then the English in the markup or the script. A marked word found nowhere keeps the word in the markup. A key a script asks for and finds nowhere shows its own name.

### Pack Timing
{: .nds-block-title}

NDS starts to load the pack of the page's language as soon as its scripts run, once per page, and the browser caches it. The link carries the `?ver=` of the NDS scripts, so a new release never shows the old text. An English page loads no pack, and a language with no pack shows the English.

The components in the bundles that load after the page shows start once the pack is in, so they write their text in the page's language. They wait 3 seconds at most, then start anyway.

### Skeleton
{: .nds-block-title}

On a page that is not in English, each marked word shows a bar in its place until the pack is in, so the page never shows English first. Expandable Content's Show More button and Empty's message are two such words. A screen reader label is written again once the pack is in, unless something changed it since. If the NDS scripts never run, the bar goes after 4 seconds.

### Plurals and Values
{: .nds-block-title}

A value can name parts that the component fills in, such as `{n}` or `{value}`. A value can also be an object of plural forms: `zero`, `one`, `two`, `few`, `many` and `other`, picked by `n` with the plural rules of the language. Only `other` is required: a form the object lacks uses `other`. Arabic uses all six, English uses `one` and `other`.

### Field Language
{: .nds-block-title}

A [Date Picker](../components/date-picker) field with `data-lang` or `lang` writes its calendar in that language, not the page's. NDS loads that language's file when the field first needs it. A `date-picker` override in `window.NDS_I18N` shows in that field too, whatever its language.

### Language Change
{: .nds-block-title}

NDS writes the words when its scripts start. When a script changes `lang` on `<html>` after that, most words stay in the old language. Load the page again to change its language.

### Frameworks
{: .nds-block-title}

Keep the markers in JSX and in Vue and Angular templates. NDS writes each word into the text node that the framework made, so a later render keeps the word. When a word changes with state, change its marker with it, such as `data-i18n="expandable.show_less"` on Show Less.

A morph, as in Livewire, Turbo or htmx, writes the server's English back into the page. `NDS.init.mount(root)` after each morph translates it again, as it starts the components in it (see [HTML Swaps](../core/init#html-swaps)). A framework that hydrates server HTML starts NDS after hydration: see [Hydration](../core/init#hydration).

NDS does not translate markers inside a shadow root.

### Missing Pack
{: .nds-block-title}

When the pack fails to load, the components show their English text. A failure other than a missing file logs `[NDS.i18n] ar failed`, with the page's language in place of `ar`. NDS looks for the pack in the `i18n/` folder beside the folder that holds `nds-main.min.js`. When your files sit somewhere else, set `NDS_I18N_PATH`.

<section id="i18n-practices" class="nds-content-section nds-doc-practices">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Best Practices</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

- Set `lang` and `dir` on `<html>` on every page. The pack follows `lang`, and the layout follows `dir`.
- Keep the `data-i18n` markers in the markup you copy from a canon. NDS writes each marked word in the page's language. Remove a marker only where you write your own word.
- Never edit the NDS scripts to change their text. Their English is only a fallback, and an upgrade replaces it.
- Use `window.NDS_I18N` to change any text. Never edit `assets/i18n/`: an NDS update replaces it.
- Set `window.NDS_I18N` before the NDS scripts run, inline in `<head>` or in a script file that loads before them. A component that already wrote its text keeps the old text.
- Write each override in the page's language: a key you set replaces that text in every language. A site with two languages writes the Arabic on its Arabic pages and the English on its English pages.
- Add to `window.NDS_I18N` with `Object.assign`, as in the example. A plain `window.NDS_I18N = { … }` drops the sections another script set.
- Set each section in one script only. A second `form` replaces the first.
- To change one element's text, use its own attribute where the component has one, such as `data-empty-message` or `data-filter-all-label`. The pack sets the text of every element.
- Keep the `{n}`-style parts of a value when you translate it. A part you drop no longer shows its value.
- Write your own markup in the page's language.
- Keep your own component's text under its own name in `window.NDS_I18N`, never in an NDS section.

<section id="i18n-api" class="nds-content-section nds-doc-api">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">API</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

### Data Attributes
{: .nds-block-title}

A marker names a word of the pack as `section.key`. NDS writes that word in the page's language, on load and whenever marked markup joins the page. A word that a script or you changed since stays as it is.

| Attribute | Element | Effect |
|---|---|---|
| `data-i18n="section.key"` | an element that holds only the word | The word replaces the element's text |
| `data-i18n-aria-label`, `-aria-description`, `-title`, `-alt`, `-placeholder`, `-label` | an element that has that attribute | The word goes in that attribute |
| `data-nds-i18n` | `<html>` | NDS sets it once the page's words are in |
{: .nds-table .nds-responsive}

### Configuration
{: .nds-block-title}

Set these on `window` before the NDS scripts. The paths are not needed when the files sit in `i18n/` beside the folder that holds `nds-main.min.js`. A language file on another origin needs CORS headers.

| Global | Default | Effect |
|---|---|---|
| `NDS_I18N` | — | Text by component and key, laid over the files: `{ forms: { required: '…' } }` |
| `NDS_I18N_PATH` | `i18n/` in the `assets/` folder the NDS scripts load from | The folder the language files load from. End it with `/`. It wins over `NDS_ASSETS_PATH` |
| `NDS_ASSETS_PATH` | the folder above the one that holds `nds-main.min.js` | The `assets/` folder. The language files load from its `i18n/` folder, and the other bundles from its `js/` folder |
{: .nds-table .nds-responsive}

### JavaScript
{: .nds-block-title}

| Method | Effect |
|---|---|
| `NDS.i18n.getStrings(component, defaults)` | Returns the text of one component, with `defaults` as its English. The methods below are on the object it returns |
| `.text(key, vars, lang)` | Returns the text for `key` in the page's language, with `vars` filled in. With `lang`, in that language: the first call loads its file |
| `.set(element, attribute, key, vars)` | Writes the word in `attribute` (`'text'` is the element's text). A word with no `vars` also gets its marker, so NDS keeps it in the page language. A word with `vars` is written again once the pack is in, unless it changed since |
| `.load(lang)` | Returns a promise of the words, in the page's language or `lang` |
| `.ready(lang)` | Returns `true` once the text of that language is in |
| `.has(key)` | Returns `true` when `defaults` has `key`. Use it for a key that comes from outside, such as a value from storage |
| `NDS.i18n.load(component, lang)` | Returns a promise of a component's words |
| `NDS.i18n.translate(root)` | Writes the words of the markers in `root` now. `NDS.init.mount()` and `refresh()` call it |
| `NDS.i18n.format(value, vars, lang)` | Fills `{name}` parts from `vars`, and picks a plural form by `vars.n` |
| `NDS.i18n.pack()` | Returns a promise of the page language's pack |
| `NDS.i18n.resolveLang(lang)` | Returns `lang`, or the page's language, as a base tag: `ar-SA` gives `ar`. A value that is not a language gives `en` |
| `NDS.i18n.isMissing(lang)` | Returns `true` when the file of `lang`, or of the page's language, did not load. The components then show English |
{: .nds-table .nds-responsive}

<script type="text/html" id="i18n-api-js" data-canon data-lang="js">
// A list that announces how many results it shows, in the page's language
const strings = NDS.i18n.getStrings('results', {
  count: { one: '{n} result', other: '{n} results' }
});
NDS.announce(strings.text('count', { n: rows.length }));
</script>

The full API is in the banner of `_js/nds-core.js`, and in the comment above `NDS.i18n` there.
