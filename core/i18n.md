<section id="i18nOverview" class="nds-content-section nds-doc-overview">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Overview</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

Components write some text themselves: error messages, button labels, screen reader labels, month names. That text lives in a pack, one JSON file per language: `assets/i18n/en.json` and `assets/i18n/ar.json`. Each component reads its own section of the pack, in the language of the page.

The page picks the language with `lang` on `<html>`. NDS loads the pack when its scripts start, so a page needs no init call. Text you write in your own markup is never translated: only text a component writes.

Pick another component when:

- you need to show a date in the page's language: [Date](../core/date)

</div>
  </div>
</section>

<section id="i18nMarkup" class="nds-content-section nds-doc-markup nds-demo-section">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Usage</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

Set the language on `<html>`. The base language names the file: `ar-SA` loads `ar.json`.

<script type="text/html" id="i18n-lang" data-canon data-preview="none">
<html lang="ar" dir="rtl">
</script>

Change a few texts with `window.NDS_I18N`, in `<head>` before the NDS scripts. Name each text by its section and key from `assets/i18n/en.json`. The keys you leave out keep the pack's text.

{%- comment %} The <script> below would end a canon, so the code sits in a capture. {% endcomment %}
{%- capture i18n_override %}
<head>
  <script>
    window.NDS_I18N = Object.assign(window.NDS_I18N || {}, {
      forms: { required: 'يرجى تعبئة هذا الحقل' },
      pagination: { prev: 'السابق', next: 'التالي' }
    });
  </script>
</head>
{% endcapture %}

<script type="text/html" id="i18n-override" data-canon data-preview="none" data-escaped>
{{ i18n_override | strip | escape }}
</script>

Add a language: copy `assets/i18n/en.json` to a file named after the language, such as `assets/i18n/fr.json`, and translate the values. The file may hold only the sections and keys you translate. The [Accessibility](../components/accessibility) panel needs its own `assets/i18n/accessibility/fr.json` too.

<script type="text/html" id="i18n-language" data-canon data-lang="json" data-preview="none">
{
  "forms": {
    "required": "Ce champ est obligatoire",
    "select_at_least": { "one": "Choisissez au moins 1 option", "other": "Choisissez au moins {n} options" }
  },
  "pagination": { "prev": "Page précédente", "next": "Page suivante", "page": "Page {n}" }
}
</script>

Give your own component its text with `NDS.i18n.strings()`. Its English goes in the call. Each other language goes in its own file at `assets/i18n/{component}/{lang}.json`, with the keys at the top level.

<script type="text/html" id="i18n-strings" data-canon data-lang="js" data-preview="none">
const strings = NDS.i18n.strings('booking', {
  title: 'Book a visit',
  seats: { one: '{n} seat left', other: '{n} seats left' }
});

heading.textContent = strings.t('title');
// set() writes the text again once the language file is in
strings.set(counter, 'text', 'seats', { n: 3 });
</script>

<section id="i18nBehavior" class="nds-content-section nds-doc-behavior">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Behavior</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

### Lookup Order
{: .nds-block-title}

A component looks for each key in this order: your `window.NDS_I18N` override, its section of the pack, then its English default. When the pack has no section for the component, the section in `en.json` takes its place. When neither has one, the component reads its own file at `assets/i18n/{component}/{lang}.json`, as [Accessibility](../components/accessibility) does. A key found nowhere shows its own name.

### Pack Timing
{: .nds-block-title}

NDS starts to load the pack of the page's language as soon as its scripts run, once per page, and the browser caches it. The link carries the `?ver=` of the NDS scripts, so a new release never shows the old text. A language with no file falls back to `en.json`.

The components in the bundles that load after the page shows start once the pack is in, so they write their text in the page's language. They wait 3 seconds at most, then start anyway.

### Skeleton
{: .nds-block-title}

Some components show text as the page opens, such as Expandable Content's Show More button or Empty's message. Each shows its loading skeleton until the pack is in. A component that your page set to `loading` itself stays in it. A screen reader label written before the pack is in is written again in the page's language, unless the component changed it since.

### Plurals and Values
{: .nds-block-title}

A value can name parts that the component fills in, such as `{n}` or `{value}`. A value can also be an object of plural forms: `zero`, `one`, `two`, `few`, `many` and `other`, picked by `n` with the plural rules of the language. Only `other` is required: a form the object lacks uses `other`. Arabic uses all six, English uses `one` and `other`.

### Field Language
{: .nds-block-title}

A [Date Picker](../components/date-picker) field with `data-lang` or `lang` writes its calendar in that language, not the page's. NDS loads that language's file when the field first needs it. A `date-picker` override in `window.NDS_I18N` shows in that field too, whatever its language.

### Language Change
{: .nds-block-title}

Components write their text when they start. When a script changes `lang` on `<html>` after that, most text stays in the old language. Load the page again to change its language.

### Missing Pack
{: .nds-block-title}

When the pack fails to load, the components show their English text, and the console logs `[NDS.i18n] ar failed`, with the page's language in place of `ar`. NDS looks for the pack in the `i18n/` folder beside the `js/` folder that the NDS scripts load from. When your files sit somewhere else, set `NDS_I18N_PATH`.

<section id="i18nPractices" class="nds-content-section nds-doc-practices">
  <div class="nds-section-wrapper">
    <div class="nds-section-head">
      <h2 class="nds-section-title">Best Practices</h2>
    </div>
    <div class="nds-section-body nds-prose" markdown="1">

- Set `lang` and `dir` on `<html>` on every page. The pack follows `lang`, and the layout follows `dir`.
- Never edit the NDS scripts to change their text. Their English is only a fallback, and an upgrade replaces it.
- Use `window.NDS_I18N` to change a few texts. Edit a copy of the pack only to change many, and copy the new keys in after each NDS release.
- Set `window.NDS_I18N` before the NDS scripts run, inline in `<head>` or in a script file that loads before them. A component that already wrote its text keeps the old text.
- Write each override in the page's language: a key you set replaces that text in every language. A site with two languages writes the Arabic on its Arabic pages and the English on its English pages.
- Add to `window.NDS_I18N` with `Object.assign`, as in the example. A plain `window.NDS_I18N = { … }` drops the sections another script set.
- Set each section in one script only. A second `forms` replaces the first.
- To change one element's text, use its own attribute where the component has one, such as `data-empty-message` or `data-filter-all-label`. The pack sets the text of every element.
- Keep the `{n}`-style parts of a value when you translate it. A part you drop no longer shows its value.
- Write your own markup in the page's language.
- Keep your own component's text in its own files, not in a section of the NDS pack. An NDS upgrade replaces the pack.
- Leave out your own component's English file, since its English is in the call. If you add one, keep it equal to the call, so a page reads the same before and after the file loads.

</div>

### Sections
{: .nds-block-title}

Each section of the pack is named after the component that reads it. The keys of each section are in [`en.json`](../assets/i18n/en.json), with the English text, and in [`ar.json`](../assets/i18n/ar.json), with the Arabic.

{: .nds-table .nds-responsive}

[Accessibility](../components/accessibility) keeps its text in `assets/i18n/accessibility/{lang}.json`, not in the pack.

### Data Attributes
{: .nds-block-title}

`NDS.i18n.load()` and `NDS.i18n.apply()` write text into the elements that carry these attributes. The accessibility panel uses them, and your own markup can too.

| Attribute | Element | Effect |
|---|---|---|
| `data-i18n="key"` | any element | The file's value for `key` replaces the element's text |
| `data-i18n-attr="attr:key"` | any element | The file's value for `key` goes in `attr`. Separate pairs with commas. Only `aria-*`, `title`, `alt`, `placeholder` and `label` are allowed |
{: .nds-table .nds-responsive}

### Configuration
{: .nds-block-title}

Set these on `window` before the NDS scripts. The paths are not needed when the files sit in `i18n/` beside the `js/` folder the scripts load from. A language file on another origin needs CORS headers. `NDSAssetBase` on [Refresh](../core/refresh) is a different global: it sets the folder the bundles load from, not the language files.

| Global | Default | Effect |
|---|---|---|
| `NDS_I18N` | — | Text by component and key, laid over the files: `{ forms: { required: '…' } }` |
| `NDS_I18N_PATH` | `i18n/` in the `assets/` folder the NDS scripts load from | The folder the language files and the component folders load from. End it with `/`. It wins over `NDS_ASSETS_BASE` |
| `NDS_ASSETS_BASE` | the folder that holds the `js/` folder of `nds-main.min.js` | The `assets/` folder. The language files load from its `i18n/` folder |
{: .nds-table .nds-responsive}

### JavaScript
{: .nds-block-title}

| Method | Effect |
|---|---|
| `NDS.i18n.strings(component, defaults)` | Returns the text of one component, with `defaults` as its English. The methods below are on the object it returns |
| `.t(key, vars, lang)` | Returns the text for `key` in the page's language, with `vars` filled in. With `lang`, in that language: the first call loads its file |
| `.set(element, attribute, key, vars)` | Writes the text in `attribute` (`'text'` is the element's text), and writes it again once the pack is in, unless it changed since |
| `.load(elements, lang)` | Loads the text. Each element shows its loading skeleton until it is in. Returns a promise |
| `.ready(lang)` | Returns `true` once the text of that language is in |
| `.has(key)` | Returns `true` when `defaults` has `key`. Use it for a key that comes from outside, such as a value from storage |
| `NDS.i18n.load(component, elements, lang)` | Loads a component's text and writes it into the `data-i18n` elements inside `elements`, which show their skeleton until then. Returns a promise of the text |
| `NDS.i18n.apply(elements, text)` | Writes `text` into the `data-i18n` elements inside `elements` |
| `NDS.i18n.format(value, vars, lang)` | Fills `{name}` parts from `vars`, and picks a plural form by `vars.n` |
| `NDS.i18n.pack()` | Returns a promise of the page language's pack |
{: .nds-table .nds-responsive}

<script type="text/html" id="i18n-api-js" data-canon data-lang="js">
// A list that announces how many results it shows, in the page's language
const strings = NDS.i18n.strings('results', {
  count: { one: '{n} result', other: '{n} results' }
});
NDS.announce(strings.t('count', { n: rows.length }));
</script>

The full API is in the banner of `_js/nds-core.js`, and in the comment above `NDS.i18n` there.
