- **`.nds-section-shape` — decide: document it or delete it.** Added 2026-03-04 (`1a8b7439`) alongside the hero-slider custom-content work, and used by nothing since: zero hits outside its own three lines in `_sass/layout/_section-layout.scss` (the `--section-shape-size` knob at :17, the sizing rule at :109). No doc page names it, so consumers cannot find it either.

  It also has a live layout bug. The title is `display: flex` + `flex-wrap: wrap`, so the text is one anonymous flex item; once that item's max-content width exceeds the line, the shape is pushed to a flex line of its own and orphans below the title, start-aligned. `.nds-center` escapes it — that variant switches the title to `flex-direction: column`, which stacks the shape on purpose and reads correctly. Deleting `flex-wrap: wrap` keeps the shape beside the wrapped text block (`align-items: center` already handles the vertical centering); making the title non-flex with an `inline-block` shape instead trails it off the last line. Both were reasoned from the box model, neither was verified in a browser — check visually before picking. Demos for all four cases (short title, long title, `.nds-full`, `.nds-center`) are already sitting in `playground.md`.

  Deleting is the cheaper answer if nothing wants it: 5 lines and a knob, no consumers, no docs, so no migration note.

- **A state write on a table wrapper restyles every row (2026-09-05).** `NDS.State.set(wrapper, …)` in `_js/nds-tables.js` (`checkTableWidth` → `handleScroll`) costs ~50 µs per body row at 1x: 137 ms for 2,800 rows across 14 tables, 174 ms for 3,000 rows across 3 (`node tmp/table-thrash-bench.mjs 1 1000 3`). It runs on the first resize delivery, on every debounced resize, and on scroll whenever the at-start/at-end tokens flip, so a 1,000-row table pays ~50 ms per state change. Likely cause: `data-state` is one attribute-name-keyed invalidation set in Chrome, and the tables sheet alone puts row and cell selectors in it (`tr[data-state~="selected"]`, `th[data-state~="sorted-asc"] .nds-sort-icon`, and the zebra rule `tr:nth-child(even of :not(… [data-state~="hidden"] …)) > td` at `_sass/components/_tables.scss:160`), so a write on the wrapper restyles every row and cell under it. The wrapper's own state rules (`_tables.scss:42–64`) are the scroll masks only, and `has-more`/`masked`/`at-start`/`at-end` on the wrapper are not documented hooks in `components/tables.md`. To do: (1) split the 137 ms into style vs layout on a padded page (`--selectors` trace or `tmp/inp-trace-agg.mjs`); (2) if it is the shared set, move the wrapper's scroll state to an own attribute the way `data-nds-scroll-lock` did on `<body>`, with the mask rules rekeyed, and a `DEPRECATIONS.md` row for the old tokens since consumer CSS may key on them; (3) re-run the bench — the write should stop scaling with rows.

## Standing decisions — do not re-propose without the named evidence

A decision lives with the artifact it governs, not here. An eval decision goes in its scenario's `baseline:` in `scenarios.md`; a grading lesson goes in `SKILL.md`; a decision already stated in source or docs is not restated at all. This section holds only what has no such home, so a full clear at release loses nothing.

- **Public-knob self-writes: sections and cards converted, the rest STAY (2026-08-23, owner call).** The audit found 605 sites across 36 knob families where a rule whose subject is the component root writes that component's own documented knob, so a consumer setting the same knob on that element loses the cascade. Fixed where it pays: `--section-*` (bf0a3204) and `--card-*` (bb3094ae), variants retuning `--_x-base` with the public check written once. Everything else stays: tags (43 sites), chips (26), avatar (25), featuredicon (23), switch (14) and ~30 smaller families are variant channels, not knobs consumers retune, and the docs teach knobs as inline `style="--knob: ..."`, which beats any stylesheet declaration anyway. Alert joined the converted set at the 1.10.0 release — its root IS the card root, so its nine status writes were card-knob self-writes the card sweep missed. Buttons (260 sites, tangled with dark `@at-root` blocks, `!important` and a11y overrides) is the one to leave alone outright — it would need rendered before/after proof, not a build. Two exceptions inside the converted families are deliberate and commented in the source: `--section-padding-block` (layouts set it on an ancestor, and an inherited public value outranks a base default) and the card width family (`--_card-width-max` chains through `--card-width`).

- **Icons STAY a standalone deferred sheet (2026-09-02, owner call).** Its 80 `--nds-icon-*` tokens on `:root` cost one whole-tree restyle when the sheet lands after the reveal (1,938 elements on the tables page), and that is the accepted price (the full-page relayout that shared the pass was the HGI `@font-face`, moved into crit later that day — see the open item; the restyle alone is what this decision keeps). Both ways out were rejected as bad trades: folding the sheet into main CSS adds 21 KB gzip (52 → 73) to the file the reveal waits for; moving only the 26 component-consumed icons into main is 3 KB gzip but a refactor of about 40 rules plus `scripts/add-icon.mjs`. Measured the fold anyway (tables page, 6.6×, paired 3-run medians): est. blocking 4.9 s → 4.4 s and the longest task 1.5 s → 0.9 s, against reveal 3.4 s → 3.7 s and a noisier LCP (2.4 s → 2.6 s median, runs from 1.3 s to 3.3 s). Interactivity buys a slower first paint; not worth it. Taking the tokens OFF `:root` (alias rules carry their own URI, only the 26 component-consumed tokens move to main at 3 KB) would remove the restyle for ~0.03 s of reveal, but `--nds-icon-{name}` is public API — `components/icons.md` documents one token per icon for consumer CSS — so dropping 54 of them from the root is a breaking change: **v2 only**, with a migration entry and the `.nds-hgi-{name}` classes as the replacement. Do not re-propose before that; reopen only on the owner's initiative.

- **Init-window whole-tree recalcs — CLOSED (2026-09-05).** Two remain on every page and both stay. The reveal (`data-nds-loaded`, ~1,900 elements) is the content's first style and the longest task on every page, and `initBudgetMs` is not a lever: 5 vs 40 on `components/tables.html` at 6.6×, three interleaved pairs plus two traced (`tmp/ab-budget.log`) — reveal 3.10 → 3.26 s (later in all three), LCP 2.36 → 2.44 s, est. blocking within 3 %, longest task unchanged at ~1.0 s (the reveal recalc itself), two to four fewer long tasks only because fewer yields merge small tasks. The icon sheet's `:root` token restyle after a cold slow-4G reveal is the price the icons decision above accepts; the one earlier request point, a head preload, puts 24 KB gz into the first wave, which is the trade it rejects. Rule kept from the 2026-09-02 fixes: never flip an inherited custom property on `<html>` or `<body>` after the reveal — key late state on an attribute whose rules reach only the elements that need it, or land the write before the stamp — and never let a `@font-face` land in a deferred sheet; declare every face in crit, where the fetch still waits for first use. Chromium facts for whoever revisits: a `@property` registration marks every element for recalc, so `inherits: false` is no way out; a font file arriving is cheap, a face being added rebuilds the font cache.

- **Tables resize thrash — CLOSED, batching saves nothing (2026-09-05).** On `components/tables.html` (14 tables) per-table read→write vs read-all→write-all is 6.0 vs 5.3 ms at 1x; padded to 2,800 rows it is 137 vs 141 ms, and 3 tables at 3,000 rows 174 vs 174 (`tmp/table-thrash-bench.mjs`). The forced pass between two tables touches only the table that just changed, and that table is styled and laid out once either way. What scales is the write itself — the open item above. Do not retry mainnav's `--nds-minimal-nav-bp` read as a lazy getter: moved from module eval to first use inside init (2026-09-02) it added a fourth full recalc (1,933 elements) to the init window, because the first `isMinimal` read lands mid-pass with the tree dirty. Not the problem on the tables page, so do not re-chase: font arrivals (all five land before the reveal), selector matching (see the skill), the ResizeObserver pool itself.
