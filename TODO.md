Two real defects fixed on the way: breadcrumb's `destroy()` left its init stamp on (one-way — the markup could never be claimed again), and several destroys left a dead instance on the element (fixed centrally in the walk, identity-guarded, so a future component cannot repeat it). **Fab closed 2026-08-15** — it was the hard one, because routing MOVES the button to a dock on `<body>`, so a docked FAB is no longer inside the view that authored it and no scan of that view can find it. `register()` now records the origin, `NDS.Fab.destroy(fabOrContainer)` puts it back (hidden again, as it shipped) and matches by where the FAB CAME FROM, and the page-level runtime (body sentinel, panel and dir observers, shared by every FAB) is released only when the last routed FAB goes. That needed a third loader shape, a registry `destroy: (root)` FUNCTION — the mirror of an owner's refresh hook — alongside the declarative `destroyEach`. Round trip covered in the check: docked → restored to its authored parent → hidden → docks removed → runtime released → routes again on the next mount. **Modal closed 2026-08-15, and Custom Select / Forms answered: they need nothing.** All three are DELEGATED — listeners installed once on `document`, matched by `closest()`, capturing no element — so there is no per-element teardown to write, and the per-element listeners they do bind (a select, a password toggle, a switch track) die with the element that holds them. Custom Select's only element state is a `_customSelectFormControl` backref stamped on the menu, which goes with the menu; Forms' is `fc._ndsLoadingRest`, stamped on the control. Neither keeps a module-level Map or observer keyed by element. **Do not add a `destroy()` to either on the "every component should have one" argument — there is nothing behind it.** Modal was different, and not for listeners: an OPEN modal holds the backdrop and the scroll lock (an inline `top` offset on body), so a view removed while it is open leaves an overlay the app cannot dismiss and a page that will not scroll, with the element that could close it already gone. `NDS.Modal.destroy(root)` releases that state immediately — no closing animation, no `nds:modal:closed`, since the view is leaving and re-entering app code mid-unmount is a hazard. Same open-state question is worth asking of any component that locks scroll or shows a backdrop. **Open, in the order they matter:** (1) Coverage is two pages (`components/filter.html`, `examples/manage-records.html`) — a component on neither is untested against the walk.
