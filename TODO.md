  - **Method names (planned 2026-10-20, not built; lands with commit 2 above).** Measured against the DOM and the libraries people and agents know best (Bootstrap, Swiper, Choices.js), so a name can be guessed without the docs. The loader names its hooks explicitly in its registry and calls only `init()` and `destroy()` by name, so a rename cannot hook a method by accident. The rules go into `PERSONA.md` as entry 9 when this is built.
    - **Rules.** They apply to namespace methods (`NDS.X.method`) and instance methods (`el.ndsX.method`) alike.
      1. camelCase, verb first. A true/false value starts with `is` or `has`. A class exposed on a namespace is PascalCase (`DatePicker.Calendar`). A name starting with `_` is internal.
      2. The noun after the verb names what the method acts on, never the namespace: `Form.validate`, not `validateForm`. Leave the noun out for the component itself (`Modal.open()`); name the part for a child (`openItem(i)`, `addFile`).
      3. An acronym is one word: `toCsv`, `isIban`, `NDS.Otp` (the Google JavaScript style guide; the DOM mixes both ways).
      4. One verb per meaning:
         - wire every element: `init()`; wire one: `create(el, opts?)`; undo: `destroy(el?)`
         - something changed, read or measure again: `refresh(el?)`. Each component does what it needs, so a caller never has to tell a content change from a size change.
         - open and close: `PERSONA.md` §3 (`open`/`close`/`toggle`/`isOpen`, `show`/`hide`, `create`/`dismiss`)
         - a value: `getValue`/`setValue`/`clear`; several values: `getValues`; anything else: `getX`/`setX`
         - on and off: `enable()`/`disable()` (Bootstrap, Swiper, Choices.js)
         - items in a list: `addX`/`removeX`
         - find an instance: `getInstance(elOrSelOrId)`, returning the instance or `null` (Bootstrap); wait for one: `whenReady(el, cb)` (as the DOM's `customElements.whenDefined`)
         - move: `goTo(i)`, `next()`, `prev()` (Bootstrap's carousel)
         - check: `validate(el)`, returning `{valid, …}`
      5. Arguments: the element first, then the values, then one options object. More than two values go in the options object. A name used in two places takes the same arguments in both.
      6. A namespace method and its instance method use the same verb. The namespace method takes the element first: `NDS.Rating.enable(el)` mirrors `el.ndsRating.enable()`.
      7. `create` returns the instance, `getInstance` returns the instance or `null`, a check returns its result, and a method that waits returns a Promise.
    - **Renames on namespaces.** `Form.validateForm` → `Form.validate`. `Form.initForm(form)` and `Form.initializeContainer(el)` → `Form.create(el)`, which takes a form or a field container. `Form.setStatus({element, status, message, permanent})` → `Form.setStatus(el, status, {message, permanent})`, as `getStatus(el)`, `clearStatus(el)` and `NDS.Status.set(el, status)`; every call already changes with the `NDS.Form` rename, so this adds no migration work. `UserFeedback.showStatus(el, status)` → `UserFeedback.setStatus(el, status)`. `Stepper.get(id)` → `Stepper.getInstance(idOrEl)`. `Stepper.previous()` → `Stepper.prev()`. `Selection.recount(list)`, `Expandable.recheckHeights()`, `Table.recheckWidths()` and `ScrollMore.checkOverflow(el)` → `refresh(el?)`, each registered as its loader `refresh` hook so `NDS.Init.refresh(el)` reaches it (Selection's no-argument call keeps working). `Code.reprocessCodeElement(el)` → `Code.highlight(el)`. `Numbers.setupCounterAnimations()` → `Numbers.initCounters()`. `Numbers.formatNumbers()` → `Numbers.formatAll()` (beside `format(el)`). `Rating.enableRating(el)` → `Rating.enable(el)`. `Progress.initCircle(el)` → `Progress.create(el)`. `Countdown.set(el, target)` → `Countdown.setTarget`. `Export.toCSV`/`toXLSHtml` → `toCsv`/`toXlsHtml`. `DatePicker.DatePickerCalendar` → `DatePicker.Calendar`. `Accessibility.ready`/`started` → `isReady`/`isStarted`.
