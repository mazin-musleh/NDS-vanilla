- **v2.0.0 is the window for breaking improvements.** A major is the one time a wrong name or a split API can be fixed rather than aliased. For each find: add a sub-item here with the problem, the fix and its migration line, then decide build or drop with the owner. Every landed break gets a Migrating entry in `CHANGELOG.md`.
  - **Filter server mode sends two key shapes.** The request carries generated options as `filter-type=a&filter-type=b` (`nds-filter.js` `filter-${filterName}`), the address bar writes `type=a,b`, and a reload or shared link sends that to the server, so a backend parses both. Kept on purpose so a key consumers read never renames (`_writeCriteriaInputs` comment), so it waits for the major. **Decided 2026-10-27: break it in v2.0.0.**
    - Why it exists: `09a3270a` (2026-01) named generated inputs `filter-{name}` to group them in the DOM, before form mode existed. Form mode then submitted that name, so a DOM detail became a request key by accident. No backend reading it is known; the risk was a guess.
    - Goal (owner, 2026-10-27): NDS invents no key and no shape. The request is what the form's own named controls send (the browser's form encoding), and the URL NDS writes is that same query. Today the request already is `FormData` (`_buildAjaxRequest`, native submit); only the names and the URL writer diverge.
    - Fix 1, names: generated options take the group's `data-filter` name, not `filter-{name}`. Also PERSONA entry 12 rule 4: a URL parameter has no prefix and takes its name from the page's hook.
    - Fix 2, URL: `syncUrlParams` writes a checkbox or switch group as repeated keys (`sector=a&sector=b`), as the form sends it, not comma-joined. This changes the published URL format, so the page also keeps reading the comma form and `filter-{name}` (`86ab7b39`): old links still open. Grep every reader of the comma form first (`_checkInputsForValues`, Pagination, examples).
    - Fix 3, sort (folds in "Server-mode sort has no canon" below): in form mode the sort reaches the request like any control. Today "Sort is never sent with the form" (`filter.md`), so a server page cannot use NDS Sort: the shortcut limits usage, against AGENTS.md Server Calls.
    - Fix 4, ranges (owner, 2026-10-27): a slider or date range sends two keys, one per end, named by the author, in the request and the URL (Stripe `created[gte]`/`[lte]`, Shopify `created_at_min`/`_max`, a plain From/To form). Every stack reads them with no split, an open end is one key, and no separator clashes with a minus or a date's dashes. Date Picker already has it: a range's two `nds-date-value` inputs, start then end, each with the author's `name` (`date-picker.md` Value for the Server); the filter canon leaves them unnamed. A filter-built slider has unnamed thumbs: give the author a place to name each end (design at build time). The page keeps reading `fee=200-1500` and `updated=a..b`, for old links only.
    - Client side and chips: no change. Client filtering, the chips, the badge and the Apply count all read `this.criteria`, never the URL or the request. What changes in client mode is the URL it writes and reads: repeated keys, two keys per range. `detail.criteria` stays as it is (a range is one `min-max` string in it, documented): changing it would break every event listener for no gain.
    - Catch found 2026-10-27: dropping the `filter-` prefix lets a group named `method` or `action` (a payment-method filter) put an input of that name in the form, and `form.method` / `form.action` then return the input (DOM clobbering): `_buildAjaxRequest` reads both and throws on `.toUpperCase()`. The prefix hid this for generated options; an authored input can trigger it today. Fix with the change: read `getAttribute('method')` / `getAttribute('action')`. A native submit is safe already (the browser reads the attributes).
    - PHP and Rails keep only the last of a repeated key unless the name ends in `[]`: that is the host stack's to handle (read the raw query, or a `[]` name), as with any HTML form.
    - Migration lines: "A server reading `filter-{name}` reads `{name}`." "A checkbox or switch group's values arrive as repeated keys, in the request and the URL, not comma-joined." "In a filter form, the sort is sent with the request." "A slider or date range arrives as two keys, under the names you give each end."
    - API check, against AGENTS.md Server Calls: `nds:filter:request` (cancelable, `criteria`, `form`, `rollback`), `nds:filter:success` and `nds:filter:error` already let a dev with CSRF, custom headers or their own client send the request themselves. The sort gap (Fix 3) is the one place the shortcut limits usage. Recheck after the fix.
    - Guard for the future: `scripts/check-filter-server-mode.mjs` checks only that no criterion is missing from the request. Make it fail when the request query differs from the URL query (keys and shape), for every group type and the sort, so a new divergence fails the check.
    - Rule to record (AGENTS.md, Server Calls in Components): a name NDS sends to a server or writes to the URL is one the author wrote (`data-filter`, an input's `name`), never one NDS invents, and its encoding is the form's own; the URL and the request are the same query. The event API (`nds:filter:request`, `detail.criteria`) stays the way to send anything else.

### Filter and Dropmenu gaps

Checked against the source 2026-10-27, and rechecked the same day for benefit vs cost and by-design. None is by design. Related: the key-shape item under v2.0.0 above.

- **Fixed in `86ab7b39`, remove at the next clean: native server mode loses the picks after the reload.** Seen in Chrome on the `filter-form` canon without `data-ajax`: Apply navigates to `?filter-sector=business`, and the new page reads only `sector`, so no option is ticked, no chip and no badge, while the server filtered the results. Fix (additive, ships now): at load, read `filter-{name}` (repeated keys) when `{name}` is absent. Priority over the items below.
- **Filter: a menu without Apply never applies.** The draft-on-close (`_addMenuDraftListeners`, `66d22888`) was written for menus with Apply; a one-group dropdown with no footer drops every pick on close. A pick never committed on change there, before `66d22888` either. Not by design: the date group already applies when no Apply is in its surface (`nds-filter.js:2120`). Fix: reuse that test; draft only in a menu holding `[data-filter-action="apply"]`; elsewhere a pick commits on change (`_commitCriteriaChange` already coalesces form submits). No new attribute. Per-surface badge: skip. Low priority: every page here has Apply.
- **Dropmenu `data-search="N"` never shows on a filter-built group.** `_setupSearch` counts rows once at setup, before Filter builds them, but `filter.md` promises `data-search="10"`. Fix: below the threshold, recount on open and inject then. The same fix lets Multiselect drop its "no number when data-driven" caveat (`multiselect.md`).
- **Server-mode sort has no canon.** Its request half is folded into the v2.0.0 key-shape item (Fix 3); the canon below follows it. `components/filter.md` ("put a `<select name="sort">` in the form") prescribes a bare native select, against Custom Select and NDS IQ; NDS styles no native select. Canon: a Dropmenu picker (`data-select-name="sort"`) in the filter form, submitted on pick. A native submit already keeps `sort=` in the URL; only AJAX mode can lose it on reload (the filter writes only its own keys; not run). Verify the request carries `sort=`.
- **Dropmenu search can't reach a collapsed filter group** (`data-search` + `data-filter-accordion`). The group's header and its count still show, and no page combines the two (the builder can). Discussed 2026-10-27: build it, small (~15 lines + doc lines), no Dropmenu event needed.
  - Layout today (`_wrapAsAccordionItem`): each group is its own `.nds-accordion` by default (`_includes/library-list.html`); groups the author wraps in one `.nds-accordion` share it, and opening one closes the rest unless `data-state="always-open"`.
  - Accordion gets `openAll()` beside `closeAll()`: opens every item, also in a one-open accordion. Needed only for the shared root; the per-group default works with `openItem(0)`. Fallback without it: `openItem()`, and a shared root shows one matching group at a time.
  - Filter, on the menu's search `input`: the first non-empty query saves which items are open and opens all; an empty query or the menu closing puts them back.
  - Dropmenu's search hides an `.nds-accordion-item` with no match, as it hides a `.nds-dropmenu-group` (Filter drops that class when it wraps a group, so today they never hide).
  - Dropmenu's first Escape clears the query without an `input` event, so Filter misses it: dispatch `input`, as the clear button already does.
- Minor: the server-mode example (`filter.md` `#services-results`) has no `nds-empty`, so a zero-result page is blank. One class on `#services-results`; the JSON handler's `replaceChildren()` then shows the placeholder too.
