- [ ] **`NDS.Init.destroy(container)` — shipped 2026-08-15, needs wider coverage before it can be called finished.** The teardown mirror of `refresh`: releases every component instance inside a container before that container is removed, returns the count. Backref components (`el.nds{Name}` + canon `destroy()`) are reached by convention with no registry entry; the five that tear down from their namespace instead opt in with `destroyEach` (Drawer, ScrollMore, Slider, Panel, Pagination), and `destroySelector` covers Slider, whose stamp sits on the container rather than the `.nds-slider` the scan finds. Declared, never probed — same reason the `refresh` hook is a registry field: `NDS.Slider.destroy()` with no argument releases every slider on the page. Verified by `scripts/check-init-destroy.mjs` (26/26), which also re-runs the mounted view to prove teardown is two-way; `check-refresh.mjs` still 28/28. Two real defects fixed on the way: breadcrumb's `destroy()` left its init stamp on (one-way — the markup could never be claimed again), and several destroys left a dead instance on the element (fixed centrally in the walk, identity-guarded, so a future component cannot repeat it). **Fab closed 2026-08-15** — it was the hard one, because routing MOVES the button to a dock on `<body>`, so a docked FAB is no longer inside the view that authored it and no scan of that view can find it. `register()` now records the origin, `NDS.Fab.destroy(fabOrContainer)` puts it back (hidden again, as it shipped) and matches by where the FAB CAME FROM, and the page-level runtime (body sentinel, panel and dir observers, shared by every FAB) is released only when the last routed FAB goes. That needed a third loader shape, a registry `destroy: (root)` FUNCTION — the mirror of an owner's refresh hook — alongside the declarative `destroyEach`. Round trip covered in the check: docked → restored to its authored parent → hidden → docks removed → runtime released → routes again on the next mount. **Modal closed 2026-08-15, and Custom Select / Forms answered: they need nothing.** All three are DELEGATED — listeners installed once on `document`, matched by `closest()`, capturing no element — so there is no per-element teardown to write, and the per-element listeners they do bind (a select, a password toggle, a switch track) die with the element that holds them.
