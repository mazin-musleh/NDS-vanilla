- [x] **Cooldown Button — the two fake-state APIs removed (owner call 2026-08-18). BREAKING.** `data-sent-title`/`data-sent-message` claimed *sent* on the click; `data-cooldown-loading` held a spinner for a fixed count that matched no real response, and with the documented wiring it DELAYED the send (the request goes out from `nds:cooldown:triggered`, which fired after the timer). Both gone, and with them `nds:cooldown:loading`, `loadingTimer`, `cfg.loading` and `ctx.triggered` — the last existed only to tell a mid-loading abort from a real one. The component now owns the throttle and the label; the page owns the request, `data-state="loading"` and the confirmation, all off `nds:cooldown:triggered`. `[data-state~="loading"]` hides the label, so the countdown ticks under the spinner and reads correctly when the state comes off. Ownership is total: the component never sets or clears `loading`, so a request outliving the countdown keeps its spinner. Doc demo, JS API tab, both examples and `form-template` all rewired. **Reasoning correction worth keeping:** the first case against both APIs leaned on "only demos use it" — rejected, the whole site is demos and NDS ships for cases it does not host.   - [x] **papercut — DONE 2026-08-18, but NOT as filed.** The report asked for `%s` to be accepted alongside `{s}`. **Rejected (user call): `{s}` stays the only token.** Two spellings for one value doubles the API surface, and `%s` implies a printf contract the component does not honour — `%d` would still fail, so the next report is the same report. The real defect the report described was **silence** ("silent until the cooldown first fires in prod"), which `%s` acceptance does not fix and a diagnostic does. Shipped instead:
    - `wire()` warns on a `data-cooldown-label` naming no `{s}` — `%s`, `%d`, `{seconds}`, `{ s }`, a typo — at page load rather than first click. Canonical `NDS CooldownButton: ` prefix; the component had zero diagnostics before, alone among 28 `_js/` files.
    - `TOKEN = /\{s\}/g` in `render()` + `stampSizers()`, fixing a second bug the report missed: the old string `.replace('{s}', …)` swapped only the FIRST occurrence, so a bilingual label naming `{s}` once per language filled the first and left the second showing literal `{s}`.
    - Implementation note worth keeping: the warn uses `search()`, not `test()`. `TOKEN` is `/g`, so `test()` carries `lastIndex` between buttons and would warn at random.

  - [x] **gap — DONE 2026-08-18.** `NDS.CooldownButton.start(btn)` always dispatched `nds:cooldown:triggered`, so the flow the doc already advertised — "start the cooldown from a flow other than the button's own click (e.g. after a form submit)" — sent a second code, because `triggered` is where the request lives. Now `start(btn, opts)`: `silent` skips only `triggered` (`tick`/`end` still fire, a resumed cooldown still has to render its seconds and re-enable), and `seconds` overrides `data-cooldown` so a cooldown can be RESUMED across a page load at its remainder. `seconds` is its own opt-in, so a button with no `data-cooldown` can be driven entirely from JS.
