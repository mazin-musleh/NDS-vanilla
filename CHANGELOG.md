## [Unreleased]

### Added
- **Accordion** — `nds-minimal` makes each heading a short button in neutral link colors, as wide as its title, with no lines between items. It takes the button sizes: 40px, 32px with `nds-md`, 24px with `nds-sm`. Use it for a short list inside other content. It does not combine with `nds-card`. See the [Accordion](https://mazin-musleh.github.io/NDS-vanilla/components/accordion.html) page.
- **Accessibility** — `NDS.Accessibility.isStarted` is true once the panel's script has started, by a press or at load. `NDS.Accessibility.isReady` is true once the panel is built and wired.
- **Accessibility** — The FAB shows how many settings are on as a badge over its icon, as the Filter button does, and adds the number to its name for screen readers. See the [Accessibility](https://mazin-musleh.github.io/NDS-vanilla/ui-shell/accessibility.html) page.- **Audit** — `NDS.init.audit()` lists what fails silently on a page, such as a filter that binds to nothing, an id a target names that does not exist, or one id on two elements. It also finds every class, attribute, id, custom property and window setting a release renamed or removed, in the markup and the site's CSS, and returns an array. Toolbar checks flag a search box that shares its line with more than one item (`toolbar-search-row`), applied filters outside their own row under the search (`toolbar-applied`), and items of different heights on one line (`toolbar-sizes`). `form-row-align` flags fields side by side whose inputs do not start level, such as one with an Info line under its label. `table-min-width` flags a `--min-width` that pushes a table's actions column out of a desktop user's view. It also flags a form with NDS fields but no `nds-form` class (`form-class`), a `data-error-message` that can never show (`error-message-unused`), a button with no icon in an `nds-minimal` action (`minimal-action-icon`), and a section title in prose (`prose-section-title`). The `button-name`, `field-label` and `img-alt` errors flag a button or link, a form field or an image that a screen reader announces with no name, and `style-blocked` warns when a Content Security Policy drops a knob's `style` attribute. See the [Audit](https://mazin-musleh.github.io/NDS-vanilla/core/audit.html) and [Migration](https://mazin-musleh.github.io/NDS-vanilla/guides/migration.html) pages.

The events are a plain Drawer list with a Date Tile on each, and the script places each one on its day and writes its tile in the calendar's calendar and language. A link card is for a navigation tile only, such as a system's icon and name: a card with an action, a price or tags keeps action buttons, and a list of page links is a Drawer. - **Cards** — `nds-reverse` on a row card (`nds-horizontal`) puts the header at the end side, for a figure that closes the row, such as a progress ring. On `.nds-card-actions`, it shows the first button last, as in a dialog's Back and Next. Stacked actions keep the markup order. See the [Cards](https://mazin-musleh.github.io/NDS-vanilla/components/card.html) page.
- **Cards** — `.nds-card-corner`, written first in `.nds-card-text`, holds a card's small extras: a status tag, a small button such as View all, or a select checkbox. Below a header it sits in the card's top end corner; otherwise it sits on the title's first line and the title wraps around it. `nds-md` and `nds-sm` on `.nds-card-text` set smaller text, and a title in the header centers on its icon. `nds-breakout` runs a drawer or a definition list to the card's edges. `nds-middle` puts short content in the middle of the card's height, such as the text beside a progress ring. See the [Cards](https://mazin-musleh.github.io/NDS-vanilla/components/card.html) page.
- **Chips** — `NDS.buildChip(label, { signal })` takes an `AbortSignal`: a chip that outlives the signal no longer calls `onRemove`. `NDS.keepChipFocus(chips, render, fallback)` serves your own list of removable chips. It runs `render`, which removes a chip, then focuses the chip that took its place, or `fallback`.
- **Code** — A CSS color value in a code block gets a swatch before it. Copy skips it. See the [Code](https://mazin-musleh.github.io/NDS-vanilla/components/code.html) page.
- **Cookies** — a Manage view with one switch per category (necessary, performance, functional, targeting), and a Done view with Undo. `NDS.consent.isAllowed(category)` and `NDS.consent.set(choice)` serve a consumer's own consent UI. `NDS.cookie.get(name)`, `set(name, value, days)` and `delete(name)` read and write a cookie without a consent check, for necessary cookies only. Text comes from the `cookies` section of `assets/i18n/{lang}.json` (moved there by the localization sweep). The panel script loads only for a visitor with no stored choice, or on the first `data-cookies-toggle` press. `data-cookies="false"` on `<html>` keeps the panel from opening by itself on that page, such as a kiosk or a TV; a trigger still opens it.
- **Cooldown Button** — an `nds-icon-only` cooldown button counts down in the icon's place. Write an empty `<span class="nds-label"></span>` before the icon: the label rests hidden, and while it counts the seconds replace the icon in the same square, so the button keeps its size. See the [Cooldown Button](https://mazin-musleh.github.io/NDS-vanilla/components/cooldown.html) page.
- **Copy** — A `data-copy-label` with no value shows Copy's own word, "Copied", in the page's language. The Share canon uses it.
- **Core** — `NDS.state.onToggle(token, scope, fn, { className })` runs `fn(el, on)` once for each real change of a `data-state` token on an element that matches `scope`, however the token was written: `NDS.state`, a bare attribute, or markup you add. `className` is a class that also spells the token. It returns `off()`, which removes the effect. `NDS.state.refresh(el, ...tokens)` runs the effects and the `onAdd` hooks for the tokens the element holds.
- **Core** — `NDS.setScrollStop(el, on)` gives a scroller with nothing focusable inside a tab stop, so the keys scroll it. A `tabindex` you wrote stays.
- **Countdown** — The time left until a deadline or until a duration ends, as text or statistic cards. The script writes the numbers, and the unit word into an empty label, in the page language. An empty `data-countdown` waits for `NDS.Countdown.setTarget()`. The Banner structure, the default, shows the units with no card around each. `data-countdown-hide` and `data-countdown-show` hide or show elements by id at zero, so an action can end with its deadline. See the [Countdown](https://mazin-musleh.github.io/NDS-vanilla/components/countdown.html) page.
- **Custom Select** — `NDS.CustomSelect.destroy(el)` undoes `create()`: pass the input or its field. The list is hidden again, and a role you wrote on the input stays.
- **Dark areas** — `data-theme="dark"` on any element renders it and its content in dark mode. Page-level DGA colors are unchanged. See the Themes page, Dark Areas.
- **Date** — `MMM` writes the month's short name, such as `Oct 24, 2026` from `MMM D, YYYY`. A Hijri month, and a language with no short names such as Arabic, shows the full name. Like `MMMM`, it only writes: `parse` and the Date Picker's typing skip a format with it. See the [Date](https://mazin-musleh.github.io/NDS-vanilla/core/date.html) page.
- **Date** — `NDS.Date` in core: `parse`, `format`, `convert` and `getToday()` for Gregorian and Hijri dates (`calendar: 'hijri'`, Umm al-Qura). `data-timezone` and `data-date-format` on `<html>` set the site's timezone and format; `data-date-format` on any element sets it for its content (`NDS.Date.getFormat(el)`). `MMMM` in a format writes the month's name. Docs: [Date](https://mazin-musleh.github.io/NDS-vanilla/core/date.html).
- **Date** — `data-date-calendar="hijri"` on a `<time datetime>` shows its date in Hijri (Umm al-Qura), in the nearest `data-date-format`, before the page shows, with no script from you; `data-date-era` adds «هـ» or AH. A `<time datetime>` with its own `data-date-format` shows the Gregorian date in that format, with month names in the page language. See the [Date](https://mazin-musleh.github.io/NDS-vanilla/core/date.html) page.
- **Date Picker** — a hidden `<input class="nds-date-value">` in `.nds-date-picker` holds the date for the server, in its own `data-date-format` and `data-calendar`, or the picker's: `data-date-format="YYYY-MM-DD" data-calendar="gregory"` sends an ISO day from a Hijri field. In a range, the first holds the start and the second the end. Text that is not a date leaves it empty; a form reset clears it.
- **Date Picker** — `data-min-date="today"` and `data-max-date="today"` use the current day in the site's timezone and the field's calendar. `today+30`, `today-1m` and `today+1y` move it by days, months or years. A day past the end of the month becomes its last day. The Form Template's Date of Birth no longer takes a future date.
- **Date Picker** — Typing takes the field's format, as in the Time Picker: `28051983` becomes `28/05/1983`, and a range adds ` - ` after the start date. A day or month digit that cannot start two digits gets a zero (`4` becomes `04/`), a digit that makes the day or month impossible is ignored, and typing in the middle of a full date replaces the digit after the cursor. After a deletion, keys go in at the cursor until the date is whole again. Arabic digits go in as 0-9. A pasted date, or a typed one when the field loses focus, written another common way takes the field's format: `1983-05-28`, `28.5.1983` and `28051983` become `28/05/1983`. See the [Date Picker](https://mazin-musleh.github.io/NDS-vanilla/components/date-picker.html) page.
- **Date Tile** — A date in a small box at the start of a list row, for exams, deadlines or events. Write `<time class="nds-date-tile" datetime="…"></time>` and the script writes the weekday, the day and the month, in the page's language and calendar; a tile you write yourself stays as written. `data-date-end` makes a range, such as 13–17 Dec or 28–3 Dec–Jan, in a wider tile, and `nds-no-weekday` hides the weekday. Each size has one width, so a list lines up; `--date-tile-width` widens it for a long Hijri month. It takes `data-status` from itself or its row. In a drawer row narrower than 400px, a tile with no size class steps down to SM. See the [Date Tile](https://mazin-musleh.github.io/NDS-vanilla/components/date-tile.html) page.
- **Dates** — `NDS.Date.toParts(date, calendar)` gives a day as `{ year, month, day }` in Gregorian or Hijri, `NDS.Date.fromParts(parts, calendar)` turns it back into a `Date`, and `NDS.Date.getMonthLength(parts, calendar)` counts the days in a month. The Date Picker and the top bar date use them. See the [Date](https://mazin-musleh.github.io/NDS-vanilla/core/date.html) page.
- **Dates** — `data-week-start` (`sun` to `sat`) on `<html>` or any element sets the first day of the week inside it; the nearest one wins, and the default stays Sunday. The Date Picker's grid starts on it. `NDS.Date.getWeekStart(el)` reads it, `NDS.Date.getWeekdayNames(lang, weekStart)` names the days from it, and `NDS.Date.getStartOfWeek(date, weekStart)` gives the first day of a date's week, and `NDS.Date.readDay(datetime)` reads the day of a `datetime` value. See the [Date Picker](https://mazin-musleh.github.io/NDS-vanilla/components/date-picker.html) page.
- **Dates** — `NDS.Date.getDayLabel(date, { calendar, locale })` names a day as a screen reader should hear it, with the month names from the string pack, so a Hijri month reads right on Android too. The Date Picker and the Calendar name their days with it. `NDS.Date.format` takes a `dddd` token for the weekday's name, and `era: true` ends a Hijri date in AH (هـ). See the [Date](https://mazin-musleh.github.io/NDS-vanilla/core/date.html) page.

- **Definition List** — `nds-highlight-value` makes the value lead: it takes the title's size and weight, and the title takes the value's look. See the [Definition List](https://mazin-musleh.github.io/NDS-vanilla/components/definition-list.html) page.

See the [Drawer](https://mazin-musleh.github.io/NDS-vanilla/components/drawer.html) page.

A click away while it runs cancels the open; the next click waits for the same request.

It writes the class and flags it needs, skips any you wrote, and `destroy()` takes back only its own. `toggle(event)` takes the click event: on a `data-anchor-cursor` menu, the menu then opens under the pointer. A submit sends the IBAN without spaces. `data-country` on any element, or on `<html>` for the whole site, sets the country they follow (`SA` without one): an IBAN without its letters gets that country's, and `NDS.FormattedInput.addIdRule()` adds the ID check of a country other than Saudi Arabia. - **Forms** — `data-format` on a `.nds-phone` field shows the number in groups: each `0` is one digit, and any other character goes between them, so `00 000 0000` shows `55 123 4567`. The field takes no more digits than the format holds. In a country picker, each item can carry its own `data-format`. See the [Formatted Input](https://mazin-musleh.github.io/NDS-vanilla/components/formatted-input.html) page.

Before, most kept the old value, chips or error, and a Custom Select could submit a value it no longer showed. A cancelled reset changes nothing.

A `method="post"` form that loads the next page in the same tab waits until that page opens; a page restored by Back takes submits again. A `data-ajax` form waits when its `nds:form:valid` listener passes the request to the new `event.detail.waitUntil(promise)`. `data-no-pending` turns it off on a POST form.

See the [Helper Classes](https://mazin-musleh.github.io/NDS-vanilla/utilities/helpers.html) page.
- **Hero** — `--overlay` on the sub hero tints its photo as on a main hero slide; the default `0.5` shows the photo at half strength, and `--overlay: 0` gives the old full photo. `--hero-image-position` picks the part of the photo in view (default `left center`). - **Images** — `assets/img/placeholder.svg`, a neutral gray image with a picture mark, for a photo slot the project has no image for yet. The template photos live in `_site/docs-assets/`, which serves the docs site: they are not in the runtime you copy from `_site/assets/`.
- **Init** — `NDS.init.ready`, a Promise that resolves once every component on the page has started, late bundles included. Page code that reads an instance such as `el.ndsTabs` at load waits on it. `NDS.init.isPending(el)` is true while `el` holds a field whose rule has not started, because its bundle is still loading or its component has not built it. A form check fails a required field in that state with "Still loading. Try again in a moment" and loads what it waits for, so the next submit can pass. A bundle that failed to load does not count, so a form is never blocked for good. `NDS.init.isOwned(el)` is true for a field whose value its component keeps, such as File Upload. See the [Init](https://mazin-musleh.github.io/NDS-vanilla/core/init.html) page.
- **Internationalization** — NDS writes its own words in the page's language. A word in the markup carries a marker: `data-i18n="section.key"` for its text, or `data-i18n-{attribute}` for `aria-label`, `aria-description`, `title`, `alt`, `placeholder` or `label`. Core writes each marked word from `assets/i18n/{lang}.json`, at start-up and in markup added later. English is the markup itself, so an English page loads no pack. NDS ships `ar.json`. `window.NDS_I18N` adds a language or changes words, key by key. On a page in another language, a marked word shows a placeholder bar until the pack is in; then `<html>` gets `data-nds-i18n`. `NDS.i18n.getStrings()` gives a site's own component its words, and `NDS.Date.getMonthNames()` / `.getWeekdayNames()` name months and days in any language. `NDS.i18n.resolveLang()` gives the page's language as a base tag (`ar-SA` gives `ar`), and `NDS.i18n.isMissing()` is true when that language's file did not load. The hidden labels and control words of the components now have Arabic. New page: `core/i18n.md`, with the list of every word.

### Changed
- **Accessibility** — The letter-spacing tile and setting are left out on a page in any language whose script joins its letters, such as Persian or Urdu, not only Arabic. The panel follows the page's language. Settings a visitor saved in a format older than v1.12.0 (`font-scale`, `smart-contrast`) are no longer converted: that visitor sees the defaults once.
- **Alert** — `--alert-stripe` and `--alert-icon-bg` are set on the alert only. They were set on every element with a status color or `data-status`, such as a tag or a field, so an alert with no status of its own took its parent's colors. Give each alert its own `data-status`.
- **Autocomplete** — With `data-strict`, text already in the field when it builds counts as a pick. A saved value still passes after the user tabs through the field.
- **Avatar** — a stacked group draws a ring in `--avatar-border` around each avatar: 1px at XS and SM, 2px at MD and LG, 4px at XL and larger; at 3XL it replaces the border.
- **Backdrop** — Removed: the `--backdrop-z-index` knob, which never applied.
- **Button** — A button fits its content in a column layout again; in 1.12 it stretched to the column's width. `.nds-full` makes one fill its container.
- **Button** — A button is never shorter than its size: 40px, 32px with `nds-md`, 24px with `nds-sm`. This holds when its height is `auto` or `100%`. A larger text size still makes it taller. Accordion headers are 56px, their set height: they were 58px.
- **Cards** — `nds-center` on a card centers its content only; the card no longer moves to the middle of its container (the global `nds-center` utility's `margin-inline: auto` leaked onto it). To center a card, use `nds-grid nds-center`, or `nds-flex nds-center` for a single card. A modal is unchanged.
- **Cards** — On phones, the gap between a card's header, content and actions is 16px; it was 24px. A card that sets `--card-gap`, and a block, prose or accordion card, keeps its own gap. Desktop is unchanged.
- **Cards** — A card's description is `--text-primary-paragraph` (was `--text-display`), and its subtitle is `--text-secondary` (was `--text-primary-paragraph`). A neutral card's title is `--text-display`, and its subtitle is `--text-secondary-paragraph`. Set `--card-text` or `--card-subtitle` to keep the old color.
- **Cards** — A row card (`nds-horizontal`) puts its header on top when it no longer fits beside 13rem of text, and an image header then fills the width. An image row card in a default 360px card now stacks instead of leaving the text a 142px column; one with an icon, an avatar or a progress ring is unchanged. Before, every row card stacked at one width, 324px. See the [Cards](https://mazin-musleh.github.io/NDS-vanilla/components/card.html) page.
- **Upload** — `setFileStatus(id, 'complete')` fires `nds:upload:success`, and `setFileStatus(id, 'error')` fires `nds:upload:error`, as an upload the script sends does. An upload your own code sends now clears the field's "wait for the upload" message when it ends. See the [Upload](https://mazin-musleh.github.io/NDS-vanilla/components/upload.html) page.
- **Dark areas** — `nds-oncolor` no longer applies to a status tag. A dark surface takes `data-theme="dark"` instead.
- **Date Picker** — The calendar's inner parts are named for the picker: `.nds-calendar-header`, `-body`, `-weekdays`, `-dates`, `-footer` and the rest are now `.nds-date-picker-header` and so on. The script builds them, so markup needs no change; a site stylesheet that targets them takes the new names.
- **Date Picker** — The calendar opens from its button, not from a click in the field, so it no longer covers the text being typed. A field with no button still opens from the input. The select caret is gone.
- **Date Picker** — Without `data-lang`, the calendar's words follow the nearest `lang`, as the Calendar's do: a picker inside `<div lang="ar">` on an English page is in Arabic. Before, only the input's own `lang` counted.
- **Drawer** — A title in a rich row wraps under its tag instead of being cut short, and the tag is XS whatever size class it carries.
- **Dropmenu** — An open menu, and a tooltip, sit in the browser's top layer (`popover`) and stay inside their wrapper in the page: nothing clips them, and CSS or scripts scoped under the component reach the menu. Page scroll carries an open menu, over the sticky main navigation, and the menu closes when its trigger leaves view. Without popover support it is fixed on screen. Where the browser supports CSS anchor positioning (Chrome 125, Safari 26), a menu or tooltip is anchored to its trigger and stays on it through any scroll, inside a fixed panel too: an open tooltip then stays open while the page scrolls and closes when its trigger leaves view. A modal that closes closes the menus inside it. A closed menu no longer listens to every click and key on the page. See the [Dropmenu](https://mazin-musleh.github.io/NDS-vanilla/components/dropmenu.html) page.
- **Dropmenu and Tooltip** — A menu or tooltip near the screen edge keeps the page gutter from it (`--nds-viewport-padding`: 32px, 16px on phones), so it lines up with the content; it kept 8px. The default `--dropmenu-max-width` is the screen less that gutter on each side.
- **File Upload** — a server upload goes `uploading` → `processing` (every byte sent) → `complete`; `create()` on a started field merges its options.
- **Filter** — The no-results alert reads "No results", "No item matches the current filters." and "Clear filters". It read "No Result", "No result for current filter criteria" and "Clear Filter".
- **Filter** — Filtering in the browser no longer shows the loading skeleton on the list for half a second. The filter applies at once, so nothing loads; a list refreshed under an applied filter, such as a live queue, flashed it on every refresh. A filter that asks a server still shows it until the response arrives.
- **Filter** — The menu's ticks are a draft until Apply: closing the menu any other way puts the applied filters back.
- **Filter** — A search keyword read from the URL keeps `& " ' < >` and its full length (it dropped them and cut at 100 characters). A shared link now opens the same list. After a sort in client mode, `nds:filter:change` carries numbers in `totalItems`, `visibleItems` and `hiddenItems` (it sent `null`). `detail.criteria` on `nds:filter:submit` and `nds:filter:request` is a copy: editing it no longer changes the filter.
- **Filter** — A group that holds a Date Picker filters by date: a range, a day, a month or a year, applied as one chip and kept in the URL as `updated=2026-10-06..2026-10-18`. The field may show Hijri; the URL and the match use Gregorian days. Beside the search box, where no Apply button reaches it, a date applies as soon as the user saves it; in a filter form it goes with the submit. A date range field is wide enough for its two dates. See the [Filter](https://mazin-musleh.github.io/NDS-vanilla/components/filter.html) page.

Without it a field's icon button kept its text padding and drew wider than tall: add the class to yours. `NDS.init.audit()` names any icon-only button that lacks it.
- **Forms** — `data-error-message` on a field is the message for its `pattern` only. An empty required field says it is required, and every other check keeps its own message: length, email or URL format, range, and the National ID, IBAN, Date Picker and Time Picker checks. On a group, it is the message when nothing is picked: a count limit, a half-filled OTP code and a file still uploading keep their own. To change those texts site-wide, set the `forms` keys in `window.NDS_I18N`. `.nds-form` sets `display: contents` with zero specificity, so your own class with `display: block` styles the form as a box.
- **Forms** — A spinner slot in a field's `.nds-form-action` is `[data-loading-slot]`. `.nds-loading` there no longer marks it, so a suffix button busy with its own request is not taken as the field's spinner. `.nds-loading` on the field stays the loading state.

- **Forms** — A `.nds-phone` field with a code submits the whole number in E.164 form (`+966551234567`). The code is the hidden input in the field's prefix: written next to a fixed `+966`, or by a country picker from the `data-value` of the picked item. A pasted full number (`+966 55…`, `00966 55…`) drops the code, or picks its country from the picker, and Italy, San Marino and Vatican City numbers keep their leading zero. A phone field without a code keeps the number as typed, leading zero included, up to 15 digits. `nds:phone:change` reports the number it submits, `{ value, countryCode, nationalNumber }`, for app state that does not read the form's data.
- **Forms** — In a menu, such as Filter's, the fields of a titled group line up with the title instead of sitting indented under it: the menu's padding already sets them apart, and a date range needs the width. On the page they stay indented.
- **Forms** — A text field with `min` or `max` on its input is checked against that range, with or without the − and + buttons: a value outside it is set to the nearest limit on blur and fails the submit. Before, only a field with the buttons was checked. On the [Text Fields](https://mazin-musleh.github.io/NDS-vanilla/components/form.html) page, the buttons are now a Buttons option of Number.

Right-click on the full image opens the browser menu again. The viewer no longer blurs the page.

Breadcrumb, footer and alert keep neutral links, and a link that is an avatar keeps its look. A plain `<a>` outside a section that relied on the neutral default turns primary: add `nds-neutral` to keep it neutral.

A card's loading pulse runs only on shown cards, a tab switch no longer measures every Expandable on the page, a Swiper image that waits for its source no longer pulses, a FAB dock that tucks near the page end no longer restyles the whole page, and the cookie panel is built while the page is idle before it opens by itself.

- **Section** — The description is `--text-primary-paragraph` (was `--text-default`). `--section-description-color` sets another color.

Other text with `/` or `:` between digits sorts as text (`12/31/2026` sorted as 12 before). ### Migrating from v1.12.0
- Replace the runtime: copy `_site/assets/` over your assets folder.
- Run `NDS.init.audit()` on every page. It lists each old name the page still uses, with its replacement. The full list by release is on the [Migration](https://mazin-musleh.github.io/NDS-vanilla/guides/migration.html) page.
- **Autocomplete** — With `data-strict`, text already in the field when it builds counts as a pick, so a server-filled value passes after the user tabs through the field. Check a value the server fills on the server, if it can be out of date.
- **Button** — A button no longer stretches to fill a column. Add `.nds-full` to one that should fill its container.
- **camelCase names** — every camelCase class, id and event is renamed to kebab case, with no aliases: `nds-wSideMenu` is `nds-has-sidemenu`, `nds-digitalStamp-*` is `nds-digital-stamp-*`, `ndsAccessibilityPanel` is `nds-accessibility-panel`, and so on. The [Migration](https://mazin-musleh.github.io/NDS-vanilla/guides/migration.html) page and `NDS.init.audit()` list each one. A few are more than a respelling: `nds-rowView` and `nds-colView` are `nds-horizontal` and `nds-vertical` (`nds-row` and `nds-col` stay the flex helper), `showZoom` is `nds-zoom-badge`, `id="ndsThemeToggle"` is the `data-theme-toggle` attribute, and `nds-cardView` on a stepper is removed (see Stepper). A custom accessibility panel needs the new collapse ids for its active counts. The source files `_DGAdigitalStamp.scss`, `nds-digitalStamp.js`, `nds-timeDate.js` and `nds-cityWeather.js` are renamed `_digital-stamp.scss`, `nds-digital-stamp.js`, `nds-time-date.js` and `nds-city-weather.js`.
- **Cards** — `.nds-card-status` and `.nds-card-checkbox` are removed: put the tag or the checkbox in `.nds-card-corner`, written first in `.nds-card-text`, the checkbox last; `.nds-full-width` on a card is removed for `.nds-full` (see Deprecations below); `.nds-user` was removed (user cards went from 224px to 360px); centred cards lost the 1.5× block padding.
- **Checkbox and Radio** — the field classes take the component names, with no aliases: `.nds-check-container` → `.nds-checkbox`, `.nds-radio-container` → `.nds-radio`, `.nds-check-group` → `.nds-checkbox-group`. The inputs take part names: `input.nds-check` → `.nds-checkbox-input`, `input.nds-radio` → `.nds-radio-input`. `.nds-radio` on an input now does nothing; it is the class of the field around it. `NDS.init.audit()` names each one.
- **Code** — the `code-example` class on a code tab panel does nothing: a panel in `.nds-tabs.nds-code` has no padding by itself. Component scripts still skip anything inside `<code>`, but no longer skip an element only because it is inside `.code-example`.
- **Code** — `data-nds-code-processed` is now `data-nds-code-highlighted`. To highlight a block again after you change its text, call `NDS.Code.highlight(code)`.
- **Core** — `NDS.triggerEvents(el)` is replaced by `NDS.setValue(el, value)`, with no alias. It writes the value and fires `input` and `change` (a checkbox or radio flips with a click, which fires them too); `{ change: false }` fires `input` only. `el.value = x; NDS.triggerEvents(el);` becomes `NDS.setValue(el, x);`. A controlled React field now sees the values NDS writes.
- **Core** — `NDS.cache` keys start with `nds-cache:` (they started with `nds_`). Old entries are not read again; they refill.
- **Cookies** — The cookie popup markup and `#ndsCookiesPopup` are removed: the script builds the panel, and a page's own `#nds-cookies-panel` in a `<template class="nds-panel-template">` replaces it. `#ndsCookiesAcceptBtn` and `#ndsCookiesDeclineBtn` become `data-cookies-action="accept|reject"`, and close is `data-panel-close`. `.nds-cookie-popup`, `.nds-cookie-popup-links` and `.nds-compact` are removed. `data-accept-title`, `data-accept-message`, `data-decline-title` and `data-decline-message` are removed: the Done view text is the `done_title` and `done` i18n keys. `NDS.consent.get()` may return `'custom'`. `nds:cookies:consent` fires on `document`, and a listener on the old popup never runs. The panel is `data-panel-static`, so an outside click does not close it.
- **Cookies** — If you copied the Google Analytics consent snippet, copy it again from the [Cookies](https://mazin-musleh.github.io/NDS-vanilla/ui-shell/cookies.html) page. It now sets all six consent keys, denies functionality and personalization storage by default, and applies a returning visitor's stored choice. The snippet reads the `nds-consent` cookie, which was `cookieConsent`. The dismissed notice is `nds-cookies-dismissed` (it was `cookieConsentDismissed`). Visitors see the consent notice once more.
- **Cookies** — the cookie helpers move out of `NDS.Cookies`, with no aliases: `NDS.Cookies.get`, `set` and `delete` are `NDS.cookie.get`, `set` and `delete`, `NDS.Cookies.getConsent()` is `NDS.consent.get()`, and `NDS.Cookies.show(view)` is `NDS.Cookies.open(view)`. `NDS.Cookies` is now the panel only: `init()`, `open()` and `close()`. Search your scripts for the old names: the audit cannot see script calls.
- **Copy** — on a copy button, `data-label` is renamed `data-copy-label` and `data-message` is renamed `data-copy-announce`. No aliases. Multiselect keeps its own `data-label`.
- **Date Picker** — "today" follows the visitor's timezone, or `data-timezone` on `<html>`. Before, it was always Riyadh: set `data-timezone="Asia/Riyadh"` to keep that. A picker with no `data-format` uses the nearest `data-date-format`, then `DD/MM/YYYY` as before.
- **Date Picker** — `CalendarConfig.hijri.gregorianToHijri(d)` → `NDS.Date.format(d, { calendar: 'hijri', format: 'DD/MM/YYYY' })`. `CalendarConfig.hijri.hijriToGregorian(y, m, d)` → `NDS.Date.parse(text, { calendar: 'hijri', format: … })`. `NDS.DatePicker.createHijriDate()` → no replacement: write a `{ day, month, year }` object.
- **Date Picker** — Only `data-calendar` picks the calendar (the nearest one, else Gregorian). A date in the other calendar is converted to the field's, whether the user types or pastes it or the page ships it in the field's `value`: `15/09/1447` in a field with no `data-calendar` becomes `04/03/2026`. A date the user writes converts when they leave the field, and a message under it names the date they wrote. Before, a year up to 1500 switched the field to Hijri. A Hijri form needs `data-calendar="hijri"` on the picker or on `<html>`. `NDS.DatePicker.Calendar` no longer has `detectCalendarTypeFromValue` or `detectCalendarTypeFromSingleValue`.
- **Date Picker** — Without `data-lang`, the calendar's words follow the nearest `lang`, not only the input's own: set `data-lang` on the input to keep one language. On `el.ndsDatePicker`, only `destroy()` stays public; its other methods and fields (`state`, `elements`, `render()` and the rest) are internal and start with `_`. Use `NDS.DatePicker.create(input)` and `destroy(input)`, the input's value and its `change` event.
- **Dates** — one `data-calendar="hijri|gregory"` sets the calendar for the content inside it, like `data-date-format`: on `<html>` for the site, or on any element. Date Picker, the top bar date and Sort read it. `.nds-hijri` on a Date Picker is removed: write `data-calendar="hijri"`. On the top bar date, `data-calendar="gregorian"` becomes `gregory`.
